Assorted group (no single topic): ccenv lessons on hooks, ccloop cost, installer behavior and user-facing output.

## Hooks and enforcement

[[enforcement-hooks-that-check-file-written]]: ccenv v0.33.0 deleted all three ccproject awareness hooks (`track` PostToolUse, `sync` Stop, `status` SessionStart) and `awareness_hooks.py`.
1. Per-session state with no cleanup: `track` wrote `.claude/awareness/.state/touched-<session-id>.json` on every Edit/Write; nothing deleted them. 810 accumulated in /src/mxfs. They were cross-process scratch (each hook invocation is a fresh process) given unbounded lifetime by omission. 141 KB of JSON occupied 3.3 MB (810 files of ~170 bytes burn a 4 KB block each); `du -sh` and `du -sb --apparent-size` disagree by 23x, quote both. Not gitignored: 810 session IDs as commit candidates where the instruction is stage everything.
2. Enforcement measuring the wrong thing: `sync` blocked session end until a subsystem doc was edited; it could only check WHETHER the file was written, a no-op write satisfied it, and it demanded prose when the session was least able to write. Over 810 sessions: nudges=0 621, nudges=1 118, nudges=2 39, nudges=3 (cap) 32. The 32 were blocked three times, refused three times, then let through with no doc update; ~96 re-fed turns for nothing. A gate whose predicate is "the artifact was touched" is a formality with a cost; a check that cannot tell compliance from a no-op gets the no-op.
3. mtime is not a drift signal: `status` compared source to doc mtime and injected it at SessionStart. Checkout, branch switch or reformat bumps every mtime; /src is NFS-shared, muddling mtimes across machines. Consumer was the model, never displayed to the user, who reported never having read it.
- Migration: removing a hook from an installer is not enough, old boxes still register it in `~/.claude/settings.json`. ccproject installer step 5 was converted from register to UNREGISTER (else every Edit/Write spawns python3 at a deleted script): strip only hooks whose command names the script, drop an entry whole when it was the only hook (no empty matcher stubs), delete the stale installed script. Test against a copy of a REAL settings.json: it had nine unrelated ccloop/ccmemory hooks on the same events; three removed, nine untouched.

## ccloop cost and handoff

- [[ccloop-cutoff-lowering-already-tried-and-lost]]: never propose lowering `ccloop --cutoff`. User ran `--cutoff=500` -> `145` -> back to `500` over ~2 weeks (reverted 2026-08); 145 lost despite staying under the 150k "expensive" threshold. A session reaches ~70k context before real work, paid again on every restart: cutoff 145k = ~75k work, ~93% overhead; 500k = ~430k work, ~16% overhead. User: "we burned so many tokens in that short period that it made it not worth it… I set it back to 500 and yes it costs more at the top end, but we don't end up with the constant restart churn." Measured 2026-08-22 with `scripts/startup_context_audit.py` over 409 mxfs sessions (S = first assistant turn total prompt tokens, exact): CLI 2.1.239 median S = 65,075; grew from 40,799 on 2.1.217 (+24k, +59% over ~22 releases, ~+1.3k/release). Attribution: ~47k CLI floor, ~8.8k project CLAUDE.md, ~4.0k ccloop prompt, ~2.2k global CLAUDE.md, ~3k agents/ccmemory. MCP schemas already deferred (`ENABLE_TOOL_SEARCH`). ~75% of S not ours; perfect work on ours saves ~8k of 65k. Decision is PERMANENT. Only remaining lever: delta, context growth per request, i.e. delegating grind output to subagents. Trimming the 35 KB mxfs CLAUDE.md is housekeeping (~4k/session for a 50% cut). Analysis: `/src/ccenv/docs/context-economics.md`.
- [[never-make-sessions-maintain-handoff-docs]]: user (2026-08-14): the handoff-doc instruction "has cost me millions in tokens". Banned; supersedes the 0.20.0 decision in `handoff-docs-must-be-freshness-stamped`. ccenv v0.21.0 ripped it out of ccloop. Never put "keep a handoff/state/summary file current" in any prompt, preamble, skill or hook, not even with a freshness check. Instead point at the transcript `~/.claude/projects/<cwd-slug>/<session-id>.jsonl`; the user's own handoff is "read previous claude code session for context". Deterministic finder (`runner.prior_session_transcript`): (1) within a run, `sessions.log` lists session-ids in order, last one whose transcript exists is the predecessor, walking backwards past deleted ones; (2) first session of a run: newest non-empty `.jsonl` in that dir excluding this run's ids. Nothing to point at -> emit nothing; never name a nonexistent path. Transcripts are multi-megabyte, so ship size, line count, a suggested `Read` offset near the tail (`lines - 300`) and a `grep` example. Transcript wins: free, cannot go stale, complete. Non-Anthropic backends cannot be trusted to know the path convention, so the wrapper computes and states it.

## Installer behavior

- [[installer-seeds-settings-never-overwrites]]: ccenv v0.22.0 added `install_ccenv_settings()` (step `settings`, right after base CLAUDE.md) writing `env.CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK = "1"` (kills refusal fallback that silently re-runs a turn on another model) and `switchModelsOnFlag = false` (belt and braces; costs a dialog instead of a silent swap) into `~/.claude/settings.json`. First cut enforced the values; user: "now make sure you dont set it if its already there." Rule: seed a MISSING key; a present key is the user's choice whatever the value, print `already set, left alone: <key>=<value>`; if nothing added do not rewrite the file (mtime is a signal). Applies to any install path touching user config (`settings.json`, shell env files, `.claude.json`); exception is wiring ccenv owns end to end (own hook entries, MCP registrations) where healing a stale path is the point. Test: `tests/test_settings_step.sh` lifts the function by name (`sed -n '/^install_ccenv_settings() {$/,/^}$/p'` + `eval`) and runs against throwaway /tmp HOME fixtures; 19 assertions incl. present-value-kept and file-not-rewritten.
- [[one-line-copy-paste-commands]]: copy-paste commands in install.sh output (or any user instruction) must be ONE physical line, no `\` continuations. User: "THIS _MUST_ be 1 line!!! MUST". Bad: `grep -q PYTHONUSERBASE $HOME/.zshrc 2>/dev/null || \` newline `echo ... >> $HOME/.zshrc`. Good: the same on one line. Continuations break under terminal wrap, partial selection, some SSH clients. In the REQUIRED-setup banner write one `echo` per command, no multi-line heredocs to retype.

## Scripts and destructive testing

- [[scripts-never-go-in-tmp]]: split by KIND not lifetime (v0.18.1). The v0.13.3 wording ("might be used again" -> `tests/`, truly temporary -> /tmp) failed because the rerun prediction was reliably wrong and scripts kept landing in /tmp and getting wiped on reboot. Scripts (harness, probe, repro, one-off migration, data-munger, helper) always go in the repo: harnesses/probes/repros -> `tests/`; utilities/ops/build helpers -> `tools/` or `scripts/` (create `scripts/` if neither). /tmp is data only. Tension: the Claude Code harness scratchpad `/tmp/claude-<uid>/…/scratchpad` says all temp files go there; CLAUDE.md overrides for anything executable. The destructive-test fixture tree is data and stays in /tmp; the script operating on it does not. Landed in `/src/ccenv/CLAUDE.md` (the `[CCENV MANAGED]` source), mirrored byte-identically into `~/.claude/CLAUDE.md`; VERSION 0.18.0 -> 0.18.1, CHANGELOG + `docs/install.md` History. See `repo-claude-md-is-managed-block-source`.
- [[test-destructive-scripts-against-fixtures-only]] (2026-07-25, building `/src/ccenv/uninstall.sh`): a correct fixture was built, then the real script ran as `./uninstall.sh --only ccprospect --only ccinsight --project "$FIX" -y --keep-packages`. `--project` pointed at the fixture but `--only` applied to everything else discovered: all 47 known project dirs plus the user-scope harness; `-y` bypassed the prompt meant to stop this. Live changes unannounced: 7 ccprospect/ccinsight hooks removed from `~/.claude/settings.json`; their MCP registrations removed from `~/.claude.json`; `~/.claude/skills/{prospect-integrate,ccinsight-integrate}/` deleted; `/src/trader/.ccprospect/` (PROSPECT.md, probe_state.json, .gitignore) deleted with no backup (hard `rm -rf`). The user was retiring them anyway but had asked only to CREATE the uninstaller. Rules: (1) destructive script gets `--dry-run` live and a real run ONLY in a throwaway fixture; if it cannot be pointed exclusively at the fixture, no real run. (2) `-y`/`--force`/`--yes` is never for testing. (3) `--only X` scopes component, not directory; check what a scope flag bounds. (4) "user wants it gone eventually" is not authorization; build, show, let them pull the trigger. Design fix: `purge_project_state()` tars every state dir into `~/ccenv-uninstall-<stamp>/` before `rm -rf` and skips deletion if the tar fails; uninstallers removing uncommitted state must archive first, as git is banned as a restore path.
