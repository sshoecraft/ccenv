## Claude Code settings and cost
### Commit attribution is two controls
- Claude Code appends `Co-Authored-By: Claude ... <noreply@anthropic.com>` (governed by `includeCoAuthoredBy`) and `Claude-Session: https://claude.ai/code/session_...` (governed by `attribution.sessionUrl`, default true). `includeCoAuthoredBy: false` alone removes only the first; verified 2026-09-10; both gone only after `attribution.sessionUrl: false`. The session URL matters: it writes a session identifier into git history permanently and pushes it to the remote. [[commit-attribution-is-two-controls]]
- Key-name trap: `coAuthoredBy` (blog posts, a web search summary) is rejected by CLI 2.1.267: `Settings validation failed: - : Unrecognized field: coAuthoredBy`. The Edit tool validates settings.json against the CLI schema, so it fails loudly. Schema is embedded in the binary at `~/.local/share/claude/versions/<ver>`, readable with `grep -ao "Claude-Session.\{0,60\}"`. `includeCoAuthoredBy` is deprecated in that schema but the only working key. [[commit-attribution-is-two-controls]]
- ccenv v0.32.0's `settings` step seeds four keys in `~/.claude/settings.json`: `includeCoAuthoredBy: false`, `attribution.commit: ""`, `attribution.pr: ""`, `attribution.sessionUrl: false`, per sub-key so a deliberately set trailer survives. Do not grep the ~100MB ELF with a greedy fixed-width lookbehind like `grep -ao ".\{700\}sessionUrl"` (catastrophic backtracking, never returns); anchor on the literal and take trailing context. [[commit-attribution-is-two-controls]]

### Quota: two weekly buckets, context-weighted cost
Measured from `/usage` and the 2.1.239 binary, 2026-08-22. [[quota-two-weekly-buckets-and-context-weighting]]
- Used: current session (5-hour) 15%, current week (all models) 19%, current week (Fable) 25%. CLI tracks six windows (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `seven_day_overage_included`, `overage`) via `GET /api/oauth/usage` (`fetchUtilization`). [[quota-two-weekly-buckets-and-context-weighting]]
- A sonnet subagent request cannot debit the Fable bucket (settles the delegation proposal's premise). Transfer, not a freebie: a Fable request debits both buckets, sonnet only all-models; delegation pays until all-models binds; at the measured mix Fable binds (25% vs 19%). `get_context_usage`/statusline expose only `five_hour` and `seven_day`, so the loop's meter cannot see the bucket that exhausts; use `/usage`. A +50% weekly-limits promo ran through 2026-08-31; headroom measured then is inflated, do not calibrate thresholds on it. [[quota-two-weekly-buckets-and-context-weighting]]
- Cost is context-weighted: `/usage` says "89% of your usage was at >150k context. Longer sessions are more expensive even when cached." The mxfs cost-audit's "~4,430 Fable requests/week" and request-count shares are proxies under one context profile; reject "every request costs the same regardless of size". Delegation's real mechanism: grind output never enters the parent's context, lowering context growth per request and extending work span inside the unchanged 500k cutoff. Full write-up `/src/ccenv/docs/context-economics.md` (also: gate subagent pass-through on `agent_id` not `agent_type`; `PreToolUse` supports non-blocking `additionalContext`; a denied tool call has already cost its request). [[quota-two-weekly-buckets-and-context-weighting]]

## CLAUDE.md and agents
### Repo CLAUDE.md is the managed-block source
- `assemble_ccenv_base_claude_md()` in install.sh (first, before components) rebuilds the `# [CCENV MANAGED]` region of `~/.claude/CLAUDE.md` every install: marker header, verbatim `cat "$SCRIPT_DIR/CLAUDE.md"`, overlay blocks, closing marker. Outside content (e.g. `[AWARENESS PROTOCOL]`) preserved. [[repo-claude-md-is-managed-block-source]]
- An edit inside the managed region survives only until the next install; policy changes must also land in `/src/ccenv/CLAUDE.md` (doubles as this repo's project instructions). Keep byte-identical: install.sh `cmp`s result vs installed file and no-ops when equal; verify by extracting the region between markers, dropping the 2 header-comment lines, diffing against the repo file. Precedent v0.13.3: the temp-file rule edited in place in `~/.claude/CLAUDE.md`, back-ported later, bundle VERSION 0.13.2->0.13.3, CHANGELOG + docs/install.md entries. Related `install-claude-md-component-owned`. [[repo-claude-md-is-managed-block-source]]

### Shipped agents embed no rules
- ccenv v0.31.0 added to RULE FOUR: subagents inherit CLAUDE.md as of session start and `.claude/agents/*.md` is registered then too, so rules a delegated task could violate must be embedded verbatim in the agent definition. None of the four shipped definitions in `/src/ccenv/agents/` does: `grind.md` (Bash/Read/Grep/Glob, model sonnet; rules only about reporting discipline: raw evidence, never silently truncate, batch aggressively; highest risk as pure shell runner), `scout.md`, `miner.md`, `memory-compactor.md` (narrower blast radius). [[shipped-agents-embed-no-rules]]
- Not broken in practice (inheritance covers pre-session rules), but breaks quietly for a rule authored mid-session. Rules that matter: git ban (RULE TWO), `find /` ban (overlay already restates for subagents), permission-prompt/`rm` shape (SEVENTEEN), `python3` (SIXTEEN), scripts never in `/tmp` (FIVE). Precedent wording: "This applies to subagents too — do not delegate a `find /` you are not allowed to run yourself." Not done: the user told v0.31.0 to add the two audited items and nothing adjacent, so the gap was reported. [[shipped-agents-embed-no-rules]]

## Handoff docs (superseded)
- `handoff-docs-must-be-freshness-stamped` is SUPERSEDED by `never-make-sessions-maintain-handoff-docs`: ccenv v0.21.0 deleted the handoff module, its two `CCLOOP_HANDOFF_*` env vars, freshness/STALE machinery, and the prompt instruction to maintain a handoff doc under `<project>/.ccloop/`. The filename is deliberately never written down (a session reading it goes looking). The 0.20.0 reasoning asked how to make a model-maintained handoff trustworthy; the answer was not to have one. ccloop names the transcript in the prompt (`runner.prior_session_block`). User: "cost me millions in tokens." [[handoff-docs-must-be-freshness-stamped]]
- Durable parts: a document the outgoing model must remember to update stops being updated (mxfs `state.md` 7 days stale across 36 ccloop runs while `state.sh` beside it ran fresh; hence `state.py` is a computed hook). A stale hand-written doc is byte-identical to a fresh one, only mtime separates them. Render a problem INTO the block, never swallow it (`state.py`). Audit every scraper for a cap: `files_edited` was the only unbounded one, capped at 60; `last_text` caps at 4,000 chars and hitting it every session proves it was never a summary. `Last 20 bash commands` (465-803 tok, a third of the resume) cut in 0.20.0, stays cut. `summarize()` runs in the runner AFTER a session exits; relay is event-driven on the wall event; no "cutoff hook" generates the resume (cutoff is only an early-relay knob). Dead: tiering rules, mtime freshness check, STALE marker, and the "1,284 tok (no handoff) -> 396 (fresh handoff)" result (priced only the prompt, never the output tokens spent rewriting the file). [[handoff-docs-must-be-freshness-stamped]]

## ccmemory
### List budget must trim every tier (0.19.0)
- Failure: `memory_list` on mxfs (1,848 memories) shipped ~14.9k tokens against a 6,000 budget while `memory_stats` said 10,490, with zero project notes and zero compiled articles: 180 entries, all `reference`/`feedback`/`user`. Paid before the first message every session and on every ccloop relay. [[list-budget-must-trim-every-tier]]
- Four defects: (1) `Store.list_all` seeded `spent` with the full always-listed set, trimmed only the remainder, broke on the first project note once those types exceeded the budget. (2) `reference` was in `ALWAYS_LIST_TYPES` yet `compile._select` ingested only `type='project'`: nothing could ever retire a reference memory (160 entries on mxfs). (3) `compiled-` articles competed with raw notes on mtime alone: 2 of 132 listed; folding retired 1,494 notes for articles then withheld. (4) `_entry_tokens` modelled `name+description+30` while the server shipped `json.dumps(indent=2)`: undercount 1.42x, inherited by `memory_stats`. Plus `count_backlog` counted every type though only `project` was actionable: backlog floor 144 vs threshold 20, nudge fired every session and could not be silenced. [[list-budget-must-trim-every-tier]]
- Invariants: a budget must trim every tier including the first; keep `ALWAYS_LIST_TYPES` small (now `("user","feedback")`; `reference` is reachable by BM25); `ALWAYS_LIST_TYPES` and `compile.COMPILABLE_TYPES` must stay complementary (`test_compilable_and_always_listed_types_are_complementary`); an unsilenceable alarm is broken (count backlog only over what compile can ingest); estimator/serializer drift silently (`test_entry_tokens_tracks_real_wire_size`). [[list-budget-must-trim-every-tier]]
- Method: do not trust self-reported cost: `memory_stats.list_tokens_actual` 10,490 vs `len(json.dumps(payload))` 14,921. Probes `tests/measure_list_payload.py` and `tests/simulate_list_policy.py` (opens `index.db` `mode=ro`, simulates policy against real stores; surfaced defect 3). Cleared: 33 mxfs rows have frontmatter `name:` differing from filename (legacy prose-titled, e.g. `feedback_commits.md` -> `name: Commits only when work is done/working`); index keys on frontmatter name and stores `path`, so `memory_get` resolves; 0 dead paths, 0 unindexed files. [[list-budget-must-trim-every-tier]]

### Prescribed remedy must not assume its own tool exists (v0.13.0 -> v0.13.1)
- `SESSION_PROTOCOL` (injected by the SessionStart hook) v0.13.0 told the model, when `memory_list` is absent: "Call `ToolSearch("select:mcp__ccmemory__memory_list")` once to try to pull in a late-connecting server." `ToolSearch` exists only with tool-search enabled; a gemma-4-26B session searched its tool list for `ToolSearch`, then burned a Bash turn whose command body was its reasoning pasted as `#` comments. [[prescribed-remedy-must-not-assume-its-own-tool-exists]]
- v0.13.0 still closed its real target (silent failure: a session with no ccmemory reads like a project with no memory, so the model concludes falsely "no prior memory"); the regression was "silently wrong" -> "visibly stuck". Do not let either excuse the other. [[prescribed-remedy-must-not-assume-its-own-tool-exists]]
- Rule for any injected "call tool X": (1) gate "IF, and only if, X is in your tool list"; (2) state absence is NORMAL, SKIP rather than hunt; (3) forbid the shell fallback by name (no shell path registers an MCP tool); (4) make the terminal state reachable from every branch (v0.13.0's "STOP" hung off the ToolSearch branch). Write injected text for the least capable model (gemma-4-26B, `instenv.prompt` fan-outs). [[prescribed-remedy-must-not-assume-its-own-tool-exists]]

## MCP
### alwaysLoad removed in v0.13.2
- `install.sh` set `alwaysLoad: true` on ccmemory from v0.6.0; `strip_always_load()` now deletes it. Correction 1 (2026-07-24, recorded, NOT acted on): decompiled from 2.1.219, the `alwaysLoad === true` tier ("regular-required") is passed `false` for nonBlocking so it blocks regardless of `MCP_CONNECTION_NONBLOCKING`, but the wait is bounded by `GVu()` = `MCP_CONNECT_TIMEOUT_MS` default 5000, per tier and shared; on expiry logs `[MCP] <r>: <c>/<n> not ready after <s>ms — proceeding; background connection continues` and starts the session anyway. It never guaranteed registration. [[mcp-alwaysload-blocks-startup]]
- Correction 2 (2026-07-25, forced removal): atrader@clyde, Claude Code driving `google/gemma-4-26B-A4B-it` via an OpenAI-compatible proxy (`chatcmpl-` tool_use_ids), 172 transcripts 2026-06-29 -> 2026-07-25. broker/journal/scheduler/searxng (unset): 353-495 successful calls each; ccusage (unset): 16 sessions, 0 rejections; ccmemory (alwaysLoad true): 0 successful memory_list ever, 122 transcripts with `No such tool available`. ccusage is the control (same bundle, installer, box, proxy, session). No deferred-tool reminder ever named the tools; server healthy (`claude mcp list` Connected, handshake 0.18s, SessionStart hook fired in all 5 newest transcripts); the model knew the name from injected protocol prose. [[mcp-alwaysload-blocks-startup]]
- Still true: no hook can gate on MCP status (SessionStart completes before the init event reporting `mcp_servers`; no post-connect hook phase, anthropics/claude-code#26112; scheduled/Remote Trigger sessions miss the deferred tool list, #41778). No load order: both tiers launch in one `Promise.all`; key order in `~/.claude.json` is meaningless. The model can enumerate its MCP surface from its tool list (split `mcp__<server>__<tool>` on `__`); `claude mcp list` is not in-session truth (spawns a second copy of every server). Enumeration cannot detect its own incompleteness; diff against a hardcoded expected set. No `claude mcp add` flag sets the field; `get`/`list` do not show it; read `~/.claude.json` and rewrite via `claude mcp remove -s user <name>` + `claude mcp add-json -s user <name> '<entry>'` (add-json will not overwrite), not `json.dump` of the 256KB file. Lesson: a memory saying "this mechanism does not do what its name says" is a finding to act on; Correction 1 sat unused a day while its predicted symptom was live and the diagnosis was re-derived badly twice. [[mcp-alwaysload-blocks-startup]]

### ccenvmcp stdlib MCP shim (2026-06-13)
- `ccenvmcp/`: ~250-line stdlib-only Python 3.9+ FastMCP-compatible shim; every release of the official `mcp` SDK needs Python >=3.10, which locked out Debian 11 / Raspberry Pi OS, RHEL/Alma/Rocky 9, Ubuntu 20.04. `mcp` was the only hard 3.9 blocker (`nats-py` >=3.7, `watchfiles>=0.21` has a 3.9 abi3 build, packages use `from __future__ import annotations`). [[ccenvmcp-stdlib-mcp-shim]]
- API `from ccenvmcp import FastMCP`: `FastMCP(name, instructions=...)`, `@app.tool()` on sync or async, `@app.tool(name=, description=, schema=)`, `app.run()`, `await app.run_stdio_async()`; newline-delimited JSON-RPC 2.0 over stdio: initialize / notifications/initialized / tools/list / tools/call / ping. [[ccenvmcp-stdlib-mcp-shim]]
- 3.9 pitfall (in `ccenvmcp/ccenvmcp/transport.py`): do not call `typing.get_type_hints()`; under `from __future__ import annotations` hints are strings like `"int | None"` and evaluating raises TypeError on 3.9. The shim parses annotation text (`_token_to_schema`: `X | None`, `Optional[X]`, `list[str]`). Tests `ccenvmcp/tests/test_transport.py`. [[ccenvmcp-stdlib-mcp-shim]]
- Consumers: ccmemory (low-level, 5 tools, explicit `schema=` to keep the memory_write `type` enum; `serve()` split into `build_app()`+`serve()`), ccusage (2 sync tools), ccteam (9 async tools, `instructions=`); `mcp` removed from deps, requires-python >=3.9; ccmemory 0.7.0, ccusage 0.2.0, ccteam 0.3.0. ccenvmcp is installed FIRST by install.sh and intentionally NOT a declared dependency (local source, never PyPI; a declared dep triggers a failing PyPI lookup). See `ccenvmcp/docs/mcp.md`, `ccmemory-debian-build-unknown-install-layout`, `no-per-component-venvs`. [[ccenvmcp-stdlib-mcp-shim]]

## ccloop CLI flags thread as params
- Established with `--model` (ccloop 0.9.0 / bundle 0.5.0). Runtime config is env-driven (`_config()` reads `CCLOOP_*`) but flags do not mutate `os.environ`; they thread as keyword params `cli.main -> runner.cmd_run / cmd_resume -> runner.loop(..., model=None)`, and `loop()` does `cfg = _config(); if model: cfg["model"] = model` (flag wins over `CCLOOP_MODEL`). [[ccloop-cli-flags-thread-as-params]]
- Recipe for the next value flag (e.g. `--effort`): (1) `cli.py` `_extract_value_flag(argv, flag, what)` pops `--flag=V` / `--flag V`, last wins, missing-value error; `_extract_cutoff`/`_extract_model` wrap it with validation (`--model` rejects empty/whitespace so `--model=` does not no-op via the falsy `if cfg[...]` in `_build_command`). (2) Thread through BOTH `cmd_run` and `--resume-run`'s `cmd_resume`. (3) Update USAGE (Options plus env var line "(--x flag wins over this)"). (4) Per-invocation like the env var: a resume does not remember the model (unlike `--cutoff`, persisted in `<run-dir>/cutoff` because guard/keepgoing hooks in other processes read it). [[ccloop-cli-flags-thread-as-params]]
- Testing: `tests/fake_claude.py` honors `FAKE_ARGS_FILE` (appends each argv as a JSON line); assert end to end, e.g. `CCLOOP_MODEL=sonnet`, pass `model="opus"`, assert `argv[argv.index("--model")+1] == "opus"`. cli parse tests stub `runner.cmd_run`/`cmd_resume` (`_stub_run`/`_stub_resume` in test_cli.py), keep signatures in sync. Never write a seam test whose fake reimplements the override logic. [[ccloop-cli-flags-thread-as-params]]
