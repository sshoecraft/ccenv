## Commit attribution is two controls (`commit-attribution-is-two-controls`)
- Claude Code appends `Co-Authored-By: Claude ... <noreply@anthropic.com>` (governed by `includeCoAuthoredBy`) and `Claude-Session: https://claude.ai/code/session_...` (governed by `attribution.sessionUrl`, defaults TRUE). `includeCoAuthoredBy: false` alone removes only the first; verified live 2026-09-10: both vanished only after `attribution.sessionUrl: false`. The session URL matters: it writes a session identifier into git history permanently and pushes it to the remote.
- Key trap: `coAuthoredBy` (no `include`), recommended by blogs and a web search summary, is REJECTED by CLI 2.1.267: `Settings validation failed: - : Unrecognized field: coAuthoredBy`. Schema is embedded in the binary at `~/.local/share/claude/versions/<ver>`, readable via `grep -ao "Claude-Session.\{0,60\}"`. `includeCoAuthoredBy` is deprecated in schema but the only working key.
- ccenv v0.32.0 `settings` step seeds four keys per sub-key (a deliberately-set trailer survives): `includeCoAuthoredBy: false`, `attribution.commit: ""`, `attribution.pr: ""`, `attribution.sessionUrl: false`, in `~/.claude/settings.json`.
- Gotcha: never `grep -ao ".\{700\}sessionUrl"` on the ~100MB ELF (catastrophic backtracking); anchor on the literal and take trailing context.

## Quota: two weekly buckets, context-weighted cost (`quota-two-weekly-buckets-and-context-weighting`)
- Measured from `/usage` and the 2.1.239 binary, 2026-08-22: current session (5-hour) 15%, current week (all models) 19%, current week (Fable) 25%. CLI tracks six windows (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `seven_day_overage_included`, `overage`) via `GET /api/oauth/usage` (`fetchUtilization`).
- A sonnet subagent request cannot debit the Fable bucket (settles the delegation proposal's premise). Fable request debits both buckets, sonnet only all-models; delegation pays until all-models binds; at measured mix Fable binds (25% vs 19%).
- `get_context_usage`/statusline expose only `five_hour` and `seven_day`, so the loop's meter cannot see the bucket that exhausts; use `/usage`. A +50% weekly-limits promo ran through 2026-08-31; do not calibrate thresholds on that headroom.
- `/usage`: "89% of your usage was at >150k context. Longer sessions are more expensive even when cached." So the mxfs cost-audit's "~4,430 Fable requests/week" and request-count shares are proxies under one stable context profile; reject "every request costs the same regardless of size". Delegation's real mechanism: grind output never enters parent context, lowering growth per request and extending work inside the unchanged 500k cutoff.
- Full write-up `/src/ccenv/docs/context-economics.md` (also: gate subagent pass-through on `agent_id` not `agent_type`; `PreToolUse` supports non-blocking `additionalContext`; a denied tool call has already cost its request).

## Handoff docs: superseded (`handoff-docs-must-be-freshness-stamped`)
- ccenv v0.21.0 deleted the handoff module, two `CCLOOP_HANDOFF_*` env vars, freshness/STALE machinery and the prompt instruction to maintain a handoff doc under `<project>/.ccloop/`. The filename is deliberately not written down anywhere in the tree (a session reading it goes looking). 0.20.0 asked how to make a model-maintained handoff trustworthy when the answer was not to have one. ccloop names the transcript in the prompt (`runner.prior_session_block`). User: "cost me millions in tokens." See `never-make-sessions-maintain-handoff-docs`.
- Durable: a doc the outgoing model must remember to update stops being updated (mxfs `state.md` 7 days stale across 36 ccloop runs while `state.sh` beside it ran fresh; hence `state.py` is a computed hook). A stale hand-written doc is byte-identical to a fresh one; only mtime differs. Render a problem INTO the block, never swallow it. Audit every scraper for a cap: `files_edited` was the only unbounded one, capped at 60; `last_text` caps at 4,000 chars, hitting it every session proves it was never a summary. `Last 20 bash commands` (465-803 tok, a third of the resume) cut in 0.20.0, stays cut. `summarize()` runs in the runner AFTER session exit; relay is event-driven on the wall event; the token cutoff is only an early-relay knob.
- Dead: tiering rules, mtime freshness check, STALE marker, and "1,284 tok (no handoff) -> 396 (fresh handoff)" (priced only the prompt, not output tokens spent rewriting the file).

## ccmemory 0.19.0: list budget must trim every tier (`list-budget-must-trim-every-tier`)
- Failure: `memory_list` on mxfs (1,848 memories) shipped ~14.9k tokens against a 6,000 budget while `memory_stats` said 10,490; listing held zero project notes and zero compiled articles (180 entries, all reference/feedback/user).
- Four defects: (1) `Store.list_all` seeded `spent` with the full always-listed set, trimming only the remainder; the loop broke at the first project note. (2) `reference` was in `ALWAYS_LIST_TYPES` while `compile._select` ingested only `type='project'`: nothing could ever retire a reference memory. (3) `compiled-` articles competed on mtime alone: 2 of 132 listed; folding retired 1,494 notes for articles then withheld. (4) `_entry_tokens` modelled `name+description+30` but server shipped `json.dumps(indent=2)`: under-counted 1.42x, and `memory_stats` inherited it. Plus `count_backlog` counted every type though only `project` was actionable: mxfs backlog floor 144 vs threshold 20; nudge fired every session and could not be silenced.
- Invariants: a budget must trim every tier including the first; keep `ALWAYS_LIST_TYPES` small, now `("user","feedback")`; it and `compile.COMPILABLE_TYPES` must stay complementary (`test_compilable_and_always_listed_types_are_complementary`); an unsilenceable alarm is broken (count backlog only over ingestible types); estimator and serializer drift (`test_entry_tokens_tracks_real_wire_size`).
- Method: do not trust self-reported cost: `memory_stats.list_tokens_actual` 10,490 vs `len(json.dumps(payload))` 14,921. Probes `tests/measure_list_payload.py`, `tests/simulate_list_policy.py` (opens `index.db` `mode=ro`, simulates policy on real stores; surfaced defect 3).
- Cleared: 33 mxfs rows have frontmatter `name:` differing from filename (e.g. `feedback_commits.md` -> `name: Commits only when work is done/working`); index keys on frontmatter name, path stored, `memory_get` resolves; 0 dead paths, 0 unindexed.
