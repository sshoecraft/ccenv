## MCP alwaysLoad removed in v0.13.2 ([[mcp-alwaysload-blocks-startup]])
- `install.sh` set `alwaysLoad: true` on ccmemory from v0.6.0; `strip_always_load()` now deletes it. Correction 1 (2026-07-24) was recorded and NOT acted on; Correction 2 (2026-07-25) forced removal.
- Correction 1, binary 2.1.219 decompiled: alwaysLoad tier is `Vyl(false, ...)` (always blocking, immune to `MCP_CONNECTION_NONBLOCKING`) but bounded: deadline `GVu()` = `MCP_CONNECT_TIMEOUT_MS` default 5000, per TIER and shared; log `[MCP] ... not ready after ${s}ms — proceeding; background connection continues`; on expiry the session starts anyway. So it never guaranteed registration.
- Correction 2: on atrader@clyde, Claude Code driving `google/gemma-4-26B-A4B-it` through an OpenAI-compatible proxy (`chatcmpl-` tool_use_ids), 172 transcripts 2026-06-29 to 2026-07-25: broker/journal/scheduler/searxng (unset) 353-495 successful calls each; ccusage (unset) used in 16 sessions, 0 rejections; ccmemory (true) 0 successful memory_list ever, 122 transcripts with `No such tool available`. ccusage is the control (same bundle, installer, box, proxy, session; only the flag differs). Not a deferral: no deferred-tool reminder named ccmemory tools. Server healthy: `claude mcp list` Connected, handshake 0.18s, SessionStart hook fired in all 5 newest transcripts; the model knew `mcp__ccmemory__memory_list` from injected protocol prose.
- Still true: no hook can gate on MCP status (SessionStart completes before the init event with `mcp_servers`; no post-connect hook phase, anthropics/claude-code#26112; scheduled/Remote Trigger sessions miss the deferred tool list, #41778). No load order (both tiers in one `Promise.all`; no "sentinel server loads last"). The model can enumerate its MCP surface from its tool list (eager = functions, deferred = named in a system-reminder; split `mcp__<server>__<tool>` on `__`); `claude mcp list` is not in-session truth (spawns second copies). Enumeration cannot detect its own incompleteness; diff against a hardcoded expected set. Setting/removing the field: no `claude mcp add` flag; read `~/.claude.json` and rewrite via `claude mcp remove -s user <name>` + `claude mcp add-json -s user <name> '<entry>'` (add-json won't overwrite); don't `json.dump` the 256KB file.
- Lesson: a memory saying "this mechanism does not do what its name says" is a finding to ACT on; Correction 1 sat unused a day while the symptom was live and diagnosis was re-derived badly twice.

## A prescribed remedy must not assume its own tool exists ([[prescribed-remedy-must-not-assume-its-own-tool-exists]])
- ccmemory v0.13.0 -> v0.13.1. `SESSION_PROTOCOL` (SessionStart hook) v0.13.0 told the model, bare imperative: Call `ToolSearch("select:mcp__ccmemory__memory_list")` once to pull in a late-connecting server. ToolSearch exists only with tool-search enabled; a gemma-4-26B session searched its tool list for ToolSearch, re-read the list, then ran a `Bash` call whose body was its own reasoning pasted as `#` comments.
- v0.13.0 still closed the SILENT failure (no memory reads looks like no memory, so the model concluded falsely); the regression "silently wrong" -> "visibly stuck" is better, not right; neither excuses the other.
- Rule for injected "call tool X": (1) gate "IF, and only if, X is in your tool list"; (2) say X's absence is NORMAL, SKIP don't hunt; (3) forbid the shell fallback by name (no shell path registers an MCP tool); (4) terminal state reachable from EVERY branch (v0.13.0's "If still unavailable, STOP" hung off the ToolSearch branch). Write for the least capable model (also drives `instenv.prompt` fan-outs).

## ccenvmcp stdlib MCP shim ([[ccenvmcp-stdlib-mcp-shim]])
- 2026-06-13: `ccenvmcp/`, ~250-line stdlib-only Python 3.9+ shim of the FastMCP slice. Reason: every `mcp` SDK release needs Python >=3.10, locking out Debian 11 / Raspberry Pi OS, RHEL/Alma/Rocky 9, Ubuntu 20.04. It was the ONLY hard 3.9 blocker (`nats-py` >=3.7; `watchfiles>=0.21` has a 3.9 abi3 build; packages use `from __future__ import annotations`).
- API `from ccenvmcp import FastMCP`: `FastMCP(name, instructions=...)`, `@app.tool()` on sync/async, `@app.tool(name=, description=, schema=)`, `app.run()`, `await app.run_stdio_async()`. Newline-delimited JSON-RPC 2.0: initialize / notifications/initialized / tools/list / tools/call / ping.
- 3.9 pitfall in `ccenvmcp/ccenvmcp/transport.py`: don't use `typing.get_type_hints()` (string hints like `"int | None"` raise TypeError on 3.9); shim parses annotation TEXT (`_token_to_schema`; `X | None`, `Optional[X]`, `list[str]`). Tests `ccenvmcp/tests/test_transport.py`.
- Consumers: ccmemory (low-level, 5 tools, explicit schema= to keep memory_write `type` enum; `serve()` split into `build_app()`+`serve()`), ccusage (2 sync), ccteam (9 async, instructions=); `mcp` dropped, requires-python >=3.9; ccmemory 0.7.0, ccusage 0.2.0, ccteam 0.3.0. Installed FIRST by top-level install.sh and deliberately NOT a declared dependency (local source, never PyPI; a declared dep triggers a failing PyPI lookup). See `ccenvmcp/docs/mcp.md`, `ccmemory-debian-build-unknown-install-layout`, `no-per-component-venvs`.

## ccloop CLI flags thread as params ([[ccloop-cli-flags-thread-as-params]])
- Established with `--model` (ccloop 0.9.0 / bundle 0.5.0). Config is env-driven (`_config()` reads `CCLOOP_*`) but flags don't mutate `os.environ`: `cli.main -> runner.cmd_run / cmd_resume -> runner.loop(..., model=None)`; after `cfg = _config()`, `if model: cfg["model"] = model` (flag beats `CCLOOP_MODEL`).
- Recipe for next value flag (e.g. `--effort`): (1) `cli.py` `_extract_value_flag(argv, flag, what)` (handles `--flag=V` and `--flag V`, last wins, missing-value error); `_extract_cutoff`/`_extract_model` are wrappers; validate in the wrapper (`--model` rejects empty/whitespace so `--model=` doesn't no-op via the falsy check in `_build_command`). (2) thread through BOTH `cmd_run` and `--resume-run`'s `cmd_resume`. (3) update USAGE (Options + env var line "(--x flag wins over this)"). (4) per-invocation like the env var: resume does NOT remember the model (unlike `--cutoff`, persisted in `<run-dir>/cutoff` since guard/keepgoing hooks in other processes read it).
- Tests: `tests/fake_claude.py` honors `FAKE_ARGS_FILE` (appends each argv as a JSON line); assert e.g. `CCLOOP_MODEL=sonnet`, `model="opus"`, `argv[argv.index("--model")+1] == "opus"`. cli parse tests stub `runner.cmd_run`/`cmd_resume` (`_stub_run`/`_stub_resume` in test_cli.py); keep signatures in sync. Don't write a seam test whose fake reimplements the override logic; use FAKE_ARGS_FILE end to end.
