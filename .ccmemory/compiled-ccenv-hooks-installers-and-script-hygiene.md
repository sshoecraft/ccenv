# ccenv assorted feedback: hooks, installer, ccloop, script hygiene

Assorted group; the notes share only that they are ccenv behavior corrections.

## Enforcement hooks that check "file was written" ([[enforcement-hooks-that-check-file-written]])
ccenv v0.33.0 deleted all three ccproject awareness hooks (`track` PostToolUse, `sync` Stop, `status` SessionStart) and `awareness_hooks.py`.
1. Per-session state files with no cleanup: `track` wrote `.claude/awareness/.state/touched-<session-id>.json` on every Edit/Write; nothing deleted them. 810 accumulated in /src/mxfs. Hooks are fresh processes, so the file was cross-process scratch memory given unbounded lifetime by omission. 141 KB of JSON used 3.3 MB on disk (~170 bytes each, 4 KB block apiece); `du -sh` and `du -sb --apparent-size` disagree 23x, quote both. Not gitignored: 810 commit candidates where the instruction is to stage everything.
2. Enforcement measuring the wrong thing: `sync` blocked session end until a subsystem doc was edited; could only check WHETHER it was written, so a no-op write satisfied it, and it demanded prose when a session is least able to write. Over 810 sessions: nudges=0 621, nudges=1 118, nudges=2 39, nudges=3 (cap) 32. The 32 were blocked three times then let through with no update; ~96 re-fed turns wasted. Generalization: a gate whose predicate is "artifact was touched" is a costly formality; if a check can't distinguish compliance from a no-op, it gets the no-op.
3. mtime is not a drift signal: `status` compared source to doc mtime and injected it at SessionStart. Checkout, branch switch or reformat bumps every mtime; /src is NFS-shared, muddling mtimes across machines. Consumer was the model; the user never saw it.
Migration: removing a hook from an installer is not enough; boxes keep it registered in `~/.claude/settings.json`. Step 5 of ccproject's installer became UNREGISTER (else every Edit/Write spawns python3 at a deleted script). Strip only hooks whose command names the script, drop an entry whole when it was the only hook (no empty matcher stubs), delete the stale installed script. Test on a copy of a REAL settings.json: nine unrelated ccloop/ccmemory hooks shared those events; three removed, nine untouched.

## Never propose lowering ccloop --cutoff ([[ccloop-cutoff-lowering-already-tried-and-lost]])
- User ran `--cutoff=500` -> `145` -> back to `500` (~2 weeks, reverted 2026-08). 145 lost despite keeping sessions under the 150k "expensive" threshold: a session reaches ~70k context before real work, a fixed cost rebuilt on every restart. Cutoff 145k -> ~75k work/session, ~93% overhead; 500k -> ~430k work, ~16% overhead. User: "we burned so many tokens in that short period that it made it not worth it... I set it back to 500 and yes it costs more at the top end, but we don't end up with the constant restart churn."
- Measured 2026-08-22 with `scripts/startup_context_audit.py` over 409 mxfs sessions (S = first assistant turn's total prompt tokens, exact): S = 65,075 median on CLI 2.1.239; 40,799 on 2.1.217, +24k (+59%) in ~22 releases, ~+1.3k per release. Attribution: ~47k CLI floor, ~8.8k project CLAUDE.md, ~4.0k ccloop session prompt, ~2.2k global CLAUDE.md, ~3k agents/ccmemory. MCP schemas already deferred (`ENABLE_TOOL_SEARCH`). ~75% of S not ours; perfect work saves ~8k of 65k.
- Standing rules: (1) don't propose lowering the cutoff, not even "until S is reduced"; (2) the only lever left is delta, context growth per request: keep grind output out of the parent via subagents; (3) trimming the 35 KB mxfs CLAUDE.md is housekeeping (~4k/session for a 50% cut). Analysis: `/src/ccenv/docs/context-economics.md`.

## Installer seeds settings, never overwrites ([[installer-seeds-settings-never-overwrites]])
- ccenv v0.22.0 added `install_ccenv_settings()` (step `settings`, right after base CLAUDE.md assembly), writing to `~/.claude/settings.json`: `env.CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK = "1"` (kills silent re-run on a different model) and `switchModelsOnFlag = false` (fallback; costs a dialog instead of a silent swap).
- Correction: first cut enforced both values. User mid-implementation: "now make sure you dont set it if its already there." Rule: seed a missing key; a present key is user choice, whatever the value; print `already set, left alone: <key>=<value>`; if nothing added, don't rewrite the file (mtime is a signal). Applies to any install path touching user config (`settings.json`, shell env files, `.claude.json`). Exception: wiring ccenv owns end to end (its hooks, MCP registrations), where healing a stale path is the point.
- Test: `tests/test_settings_step.sh` lifts the function out of `install.sh` (`sed -n '/^install_ccenv_settings() {$/,/^}$/p'` + `eval`) and runs it on throwaway /tmp HOME fixtures; 19 assertions incl. present-value-kept and file-not-rewritten.

## Never make sessions maintain handoff docs ([[never-make-sessions-maintain-handoff-docs]])
- User, 2026-08-14: the handoff-doc instruction "has cost me millions in tokens". Supersedes the 0.20.0 decision in `handoff-docs-must-be-freshness-stamped`. ccenv v0.21.0 removed it from ccloop. Never put "keep a handoff/state/summary file current" into any prompt, preamble, skill or hook, not even with freshness checks.
- Instead: the transcript `~/.claude/projects/<cwd-slug>/<session-id>.jsonl` is the handoff; user's long-standing handoff is "read previous claude code session for context". ccloop `runner.prior_session_transcript`: (1) within a run, `sessions.log` holds session-ids in order, last one whose transcript still exists is the predecessor (walk backwards past deleted ones); (2) first session of a run: newest non-empty `.jsonl` in the project dir excluding this run's ids. Nothing to point at -> emit nothing; never name a nonexistent path.
- A transcript is multi-MB: ship pointer with size, line count, suggested `Read` offset near the tail (`lines - 300`) and a `grep` example.
- Why it wins: free, cannot go stale (no mtime checks/STALE markers/scraped fallback), complete (tool results and reasoning). Caveat: non-Anthropic API backends driving `claude` can't be trusted to know their transcript path, so the wrapper computes and states it.

## Scripts never go in /tmp ([[scripts-never-go-in-tmp]])
- v0.13.3 wording ("might be reused -> `tests/`, truly temporary -> /tmp") failed: predicting reuse was reliably wrong, every script came with a throwaway story and got wiped on reboot. v0.18.1 splits by kind: scripts (harness, probe, repro, one-off migration, data-munger, helper) go in the repo: harnesses/probes/repros in `tests/`, utilities/ops/build helpers in `tools/` or `scripts/` (create `scripts/` if neither). /tmp is data only: scratch output, blobs, throwaway fixtures, dumps.
- Tension: the harness scratchpad `/tmp/claude-<uid>/.../scratchpad` says all temp files go there; CLAUDE.md overrides for anything executable. Compatible with [[test-destructive-scripts-against-fixtures-only]]: the fixture tree is data and stays in /tmp, the script operating on it does not.
- Landed in `/src/ccenv/CLAUDE.md` (`[CCENV MANAGED]` source) and mirrored byte-identically into `~/.claude/CLAUDE.md`; VERSION 0.18.0 -> 0.18.1, CHANGELOG + `docs/install.md` History. See `repo-claude-md-is-managed-block-source`.

## Test destructive scripts against fixtures only ([[test-destructive-scripts-against-fixtures-only]])
- Incident 2026-07-25 building `/src/ccenv/uninstall.sh`: ran `./uninstall.sh --only ccprospect --only ccinsight --project "$FIX" -y --keep-packages`. `--project` pointed at the fixture but `--only` still applied to all 47 known project dirs plus user-scope harness; `-y` bypassed the prompt. Unannounced live changes: `~/.claude/settings.json` 7 ccprospect/ccinsight hooks removed; `~/.claude.json` both MCP registrations removed; `~/.claude/skills/{prospect-integrate,ccinsight-integrate}/` deleted; `/src/trader/.ccprospect/` (PROSPECT.md, probe_state.json, .gitignore) deleted with no backup. User was retiring them anyway but had asked only to CREATE the uninstaller and handle archiving themselves.
- Rules: (1) destructive script gets `--dry-run` live and a real run ONLY in a throwaway fixture; if it can't be pointed exclusively at the fixture, no real run. (2) `-y`/`--force`/`--yes` never for testing. (3) `--only X` scopes component, not directory; check what a scope flag bounds. (4) "User wants it gone eventually" is not authorization now.
- Design lesson: `purge_project_state()` now tars every state dir into `~/ccenv-uninstall-<stamp>/` before `rm -rf`, skipping deletion if the tar fails. Uninstallers removing state with no other copy must archive first; `git` is banned as a restore path.

## One-line copy-paste commands ([[one-line-copy-paste-commands]])
- Copy-paste commands in install.sh output (or any user-facing instruction) must be ONE physical line, no `\` continuations. User: "THIS _MUST_ be 1 line!!! MUST". Wrong: `grep -q PYTHONUSERBASE $HOME/.zshrc 2>/dev/null || \` + newline + `echo ...`. Right: `grep -q PYTHONUSERBASE $HOME/.zshrc 2>/dev/null || echo 'export PYTHONUSERBASE="$HOME/.local"' >> $HOME/.zshrc`.
- Why: continuations break under terminal wrap, partial selection, some SSH clients. Apply: in install.sh's REQUIRED-setup banner write one `echo` per command, no multi-line heredocs the user must retype.
