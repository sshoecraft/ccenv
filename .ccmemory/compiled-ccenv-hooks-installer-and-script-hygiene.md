## Enforcement hooks that check "file written" (ccproject, removed in v0.33.0)
ccenv v0.33.0 deleted all three ccproject awareness hooks (`track` PostToolUse, `sync` Stop, `status` SessionStart) and `awareness_hooks.py`. [[enforcement-hooks-that-check-file-written]]
1. Per-session state with no cleanup: `track` wrote `.claude/awareness/.state/touched-<session-id>.json` on every Edit/Write; nothing deleted them; 810 accumulated in /src/mxfs. Each hook is a fresh process, so it was cross-process scratch with unbounded lifetime by omission. Size: 141 KB of JSON occupied 3.3 MB (810 files of ~170 bytes burn a 4 KB block each); `du -sh` vs `du -sb --apparent-size` differ 23x, quote both. Not gitignored: 810 commit candidates where the instruction is stage everything. [[enforcement-hooks-that-check-file-written]]
2. Wrong measure: `sync` blocked session end until a subsystem doc was edited; it could check only whether the file was written, so a no-op write satisfied it, and it demanded prose when a session is least able to write. Measured over 810 sessions: nudges=0 621, nudges=1 118, nudges=2 39, nudges=3 (cap) 32; the 32 were blocked three times then let through with no doc update, ~96 re-fed turns for nothing. Generalize: a gate whose predicate is "artifact was touched" is a formality with a cost; a check that cannot tell compliance from a no-op gets the no-op. [[enforcement-hooks-that-check-file-written]]
3. mtime is not a drift signal: `status` compared source mtime to doc mtime and injected it at SessionStart; checkout, branch switch or reformat bumps every mtime; /src is NFS-shared, muddling mtimes across machines. Its consumer was the model, never displayed to the user. [[enforcement-hooks-that-check-file-written]]
- Migration: removing a hook from an installer is not enough; boxes that ran the old installer still have it in `~/.claude/settings.json`. Step 5 of ccproject's installer became UNREGISTER (else every Edit/Write spawns python3 at a deleted script): strip only hooks whose command names the script, drop an entry whole when it was the only hook (no empty matcher stubs), delete the stale installed script. Test against a copy of a REAL settings.json: it had nine unrelated ccloop/ccmemory hooks on the same events; three removed, nine untouched. [[enforcement-hooks-that-check-file-written]]

## Never propose lowering ccloop --cutoff
- User's experiment (~2 weeks, reverted 2026-08): `--cutoff=500` -> `145` -> back to `500`. 145 lost despite staying under the 150k "expensive" threshold. A session reaches ~70k tokens before real work, a fixed cost rebuilt on each restart: cutoff 145k -> ~75k work/session, ~93% overhead; cutoff 500k -> ~430k work, ~16% overhead. User: "we burned so many tokens in that short period that it made it not worth it... I set it back to 500 and yes it costs more at the top end, but we don't end up with the constant restart churn." [[ccloop-cutoff-lowering-already-tried-and-lost]]
- Measured 2026-08-22 with `scripts/startup_context_audit.py` over 409 mxfs sessions (S = first assistant turn's total prompt tokens, exact): CLI 2.1.239 median S = 65,075. S grows with the CLI: 40,799 on 2.1.217 -> 65,075 on 2.1.239, +24k (+59%) in ~22 releases, ~+1.3k/release. Attribution: ~47k CLI floor, ~8.8k project CLAUDE.md, ~4.0k ccloop session prompt, ~2.2k global CLAUDE.md, ~3k agents/ccmemory. MCP schemas already deferred (`ENABLE_TOOL_SEARCH`; every sampled session used ToolSearch). ~75% of S not ours; perfect work saves ~8k of 65k. [[ccloop-cutoff-lowering-already-tried-and-lost]]
- Standing rules: (1) do not propose lowering the cutoff, not even "until S is reduced"; (2) the only lever left is delta, context growth per request: keep grind output out of the parent via subagent delegation; (3) trimming the 35 KB mxfs CLAUDE.md is housekeeping (~4k/session for a 50% cut). Analysis: `/src/ccenv/docs/context-economics.md`. [[ccloop-cutoff-lowering-already-tried-and-lost]]

## Installer seeds settings, never overwrites
- ccenv v0.22.0 added `install_ccenv_settings()` to `install.sh` (step `settings`, right after base CLAUDE.md assembly), writing to `~/.claude/settings.json`: `env.CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK = "1"` (kills refusal fallback that silently re-runs a turn on another model) and `switchModelsOnFlag = false` (belt and braces; costs a dialog instead of a silent swap). [[installer-seeds-settings-never-overwrites]]
- Correction: first cut enforced both values and rewrote a differing key. User cut in: "now make sure you dont set it if its already there." Rule: seed only a missing key; a present key is a user choice, left whatever the value, printing `already set, left alone: <key>=<value>`. When nothing was added, do not rewrite the file (mtime is a signal). Applies to any install path touching user config (`settings.json`, shell env files, `.claude.json`): add-if-missing, never enforce. Exception: wiring ccenv owns end to end (its hook entries, MCP registrations), where healing a stale path is the point. [[installer-seeds-settings-never-overwrites]]
- Test `tests/test_settings_step.sh` lifts the function by name (`sed -n '/^install_ccenv_settings() {$/,/^}$/p'` + `eval`) and runs it against throwaway /tmp HOME fixtures; 19 assertions incl. present-value-kept and file-not-rewritten. [[installer-seeds-settings-never-overwrites]]

## Never make sessions maintain handoff docs
- User, 2026-08-14: the handoff-document instruction "has cost me millions in tokens"; banned. Supersedes the 0.20.0 decision in `handoff-docs-must-be-freshness-stamped`; ccenv v0.21.0 removed it from ccloop. Never put "keep a handoff/state/summary file current" in any prompt, preamble, skill or hook, not even with freshness check or "short". [[never-make-sessions-maintain-handoff-docs]]
- Instead point at the transcript `~/.claude/projects/<cwd-slug>/<session-id>.jsonl`. User's own handoff: "read previous claude code session for context". ccloop `runner.prior_session_transcript`: (1) within a run, `sessions.log` holds ids in order, the last whose transcript still exists is the predecessor (walk backwards past deleted ones); (2) first session of a run: newest non-empty `.jsonl` in the project dir excluding this run's ids. Nothing to point at -> emit nothing; never name a nonexistent path. [[never-make-sessions-maintain-handoff-docs]]
- Multi-megabyte JSONL: the pointer must ship size, line count, a suggested `Read` offset near the tail (`lines - 300`), and a `grep` example. Transcript wins: free, cannot go stale, complete (tool results and reasoning). Non-Anthropic API backends driving `claude` cannot be trusted to know their transcript path, so the wrapper computes and states it. [[never-make-sessions-maintain-handoff-docs]]

## Scripts never go in /tmp
- v0.13.3 wording ("might be used again" -> `tests/`, truly temporary -> /tmp) failed: the prediction was reliably wrong and scripts kept landing in /tmp and getting wiped. v0.18.1 splits by kind: every script (harness, probe, repro, one-off migration, data-munger, helper) goes in the repo: harnesses/probes/repros in `tests/`, utilities/ops/build in `tools/` or `scripts/` (create `scripts/` if neither). /tmp is data only: scratch output, downloaded blobs, throwaway fixtures, intermediate dumps. [[scripts-never-go-in-tmp]]
- Tension: the harness scratchpad `/tmp/claude-<uid>/.../scratchpad` says all temp files go there; CLAUDE.md overrides for anything executable. Destructive-test fixture trees are data and stay in /tmp; the script operating on them does not. Landed in `/src/ccenv/CLAUDE.md` (the `[CCENV MANAGED]` source) and mirrored byte-identically into `~/.claude/CLAUDE.md`; VERSION 0.18.0->0.18.1, CHANGELOG + `docs/install.md` History. See `repo-claude-md-is-managed-block-source`. [[scripts-never-go-in-tmp]]

## Test destructive scripts against fixtures only
- 2026-07-25, building `/src/ccenv/uninstall.sh`: after building a correct fixture, ran `./uninstall.sh --only ccprospect --only ccinsight --project "$FIX" -y --keep-packages`. `--project` pointed at the fixture but `--only` still applied to everything else discovered (all 47 known project dirs plus user-scope harness); `-y` bypassed the prompt. Live changes: 7 ccprospect/ccinsight hooks removed from `~/.claude/settings.json`; their MCP registrations removed from `~/.claude.json`; `~/.claude/skills/{prospect-integrate,ccinsight-integrate}/` deleted; `/src/trader/.ccprospect/` (PROSPECT.md, probe_state.json, .gitignore) deleted with no backup (hard `rm -rf`). The user was retiring them anyway but had asked only to CREATE the uninstaller. [[test-destructive-scripts-against-fixtures-only]]
- Rules: (1) `--dry-run` on live, real run ONLY inside a throwaway fixture; if the script cannot be pointed exclusively at the fixture, no real run. (2) `-y`/`--force`/`--yes` never for testing. (3) `--only X` scopes component, not directory; check what a scope flag bounds. (4) "User wants it gone eventually" is not authorization; build, show, let them pull the trigger. [[test-destructive-scripts-against-fixtures-only]]
- Design lesson: `purge_project_state()` now tars every state dir into `~/ccenv-uninstall-<stamp>/` before `rm -rf` and skips deletion if tar fails; uncommitted state is otherwise unrecoverable, and `git` is banned as restore. [[test-destructive-scripts-against-fixtures-only]]

## One-line copy-paste commands
- Copy-paste commands in install.sh output (or any user instruction) must be one physical line, no `\` continuations. User: "THIS _MUST_ be 1 line!!! MUST". Bad: `grep -q PYTHONUSERBASE $HOME/.zshrc 2>/dev/null || \` newline `echo 'export PYTHONUSERBASE="$HOME/.local"' >> $HOME/.zshrc`; good: the same on one line. Why: continuations break under terminal wrap, partial selection, some SSH pastes, reading aloud. In install.sh's REQUIRED-setup banner write one `echo` per command, no `\` splits, no multi-line heredocs for the user to retype. [[one-line-copy-paste-commands]]
