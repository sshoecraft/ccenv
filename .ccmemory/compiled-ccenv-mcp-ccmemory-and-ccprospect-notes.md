## ccmemory list budget must trim every tier (0.19.0)
Source: [[list-budget-must-trim-every-tier]]
- Failure: `memory_list` on mxfs (1,848 memories) shipped ~14.9k tokens against a 6,000-token budget while `memory_stats` said 10,490; listing held zero project notes and zero compiled articles: 180 entries, all reference/feedback/user. Paid before the first message every session and on every ccloop relay.
- Four defects: (1) `Store.list_all` seeded `spent` with the full always-listed set and trimmed only the remainder; once those exceeded the budget the loop broke on the first project note (budget capped nothing and starved other tiers). (2) `reference` was in `ALWAYS_LIST_TYPES` (exempt from folding) while `compile._select` ingested only `type='project'`: nothing could ever retire a reference memory (write-only type). (3) `compiled-` articles competed with raw notes on mtime alone: 2 of 132 listed; folding retired 1,494 notes for articles then withheld. (4) `_entry_tokens` modelled `name+description+30`, server shipped `json.dumps(indent=2)`: under-counted 1.42x and `memory_stats` inherited it. Plus `count_backlog` counted every type while only `project` was actionable: mxfs backlog floor 144 vs threshold 20; the nudge fired every session and could not be silenced by compacting.
- Invariants: a budget must be able to trim every tier including the first (else advisory); keep `ALWAYS_LIST_TYPES` small, now `("user","feedback")` (reference is durable and BM25 search reaches it); `ALWAYS_LIST_TYPES` and `compile.COMPILABLE_TYPES` must stay complementary (`test_compilable_and_always_listed_types_are_complementary`); an unsilenceable alarm is broken, count backlog only over what compile can ingest; estimator and serializer drift (`test_entry_tokens_tracks_real_wire_size`).
- Diagnostics: do not trust self-reported cost: `memory_stats.list_tokens_actual` 10,490 vs `len(json.dumps(payload))` 14,921. Probes `tests/measure_list_payload.py` and `tests/simulate_list_policy.py` (opens `index.db` `mode=ro`, simulates policy changes on real stores; surfaced defect 3).
- Cleared: 33 mxfs rows have frontmatter `name:` differing from filename (legacy prose-titled, e.g. `feedback_commits.md` -> `name: Commits only when work is done/working`); index keys on frontmatter name and stores `path`, so `memory_get` resolves; 0 dead paths, 0 unindexed files.

## MCP alwaysLoad: removed in ccenv v0.13.2
Source: [[mcp-alwaysload-blocks-startup]]
- `install.sh` set `alwaysLoad: true` on ccmemory from v0.6.0; `strip_always_load()` now deletes the field. Correction 1 (2026-07-24) was recorded and not acted on; Correction 2 (2026-07-25) forced removal.
- Correction 1, a deadline not a barrier (decompiled binary 2.1.219): `o = !su(process.env.MCP_CONNECTION_NONBLOCKING)`; alwaysLoad configs are tier "regular-required", others "regular"; both in one `Promise.all`; `Vyl(nonBlocking, ...)` gets literal `false` for the alwaysLoad tier (always blocking, immune to env) but bounded: `GVu()` = `MCP_CONNECT_TIMEOUT_MS` default 5000; `awaitEachWithDeadline`; on expiry logs `[MCP] <r>: <c>/<n> not ready after <s>ms — proceeding; background connection continues`. Deadline per TIER, SHARED; session starts anyway; never guaranteed registration.
- Correction 2, on non-Anthropic models it erases the tool surface. Measured on atrader@clyde: Claude Code driving `google/gemma-4-26B-A4B-it` via an OpenAI-compatible proxy (`chatcmpl-` tool_use_ids), 172 transcripts 2026-06-29 to 2026-07-25. broker/journal/scheduler/searxng (unset): 353-495 successful calls each; ccusage (unset): 16 sessions, 0 rejections; ccmemory (alwaysLoad true): 0 successful memory_list ever; 122 transcripts with `No such tool available`. ccusage is the control (same bundle, installer, box, proxy, session; only the flag differs). Not a deferral: no deferred-tool reminder named ccmemory tools. Server healthy: `claude mcp list` Connected, handshake 0.18s, SessionStart hook fired in all 5 newest transcripts; the model knew `mcp__ccmemory__memory_list` from injected protocol prose.
- Still true: no hook can gate on MCP status (SessionStart completes BEFORE the init event reporting `mcp_servers`; no post-MCP-connect hook phase, anthropics/claude-code#26112; scheduled/Remote Trigger sessions miss the deferred tool list, #41778). No load order exists (single concurrent `Promise.all`; `~/.claude.json` key order meaningless; "sentinel server that loads last" not implementable). The model can enumerate its own MCP surface from its tool list (eager as functions, deferred named in a system-reminder; split `mcp__<server>__<tool>` on `__`); `claude mcp list` is NOT in-session truth (spawns a second copy of every server). Enumeration cannot detect its own incompleteness; diff against a hardcoded expected set. Setting/removing the field: no `claude mcp add` flag; `get`/`list` do not surface it; read `~/.claude.json` and rewrite via `claude mcp remove -s user <name>` + `claude mcp add-json -s user <name> '<entry>'` (add-json refuses to overwrite); prefer over `json.dump` of the 256KB file.
- Lesson: a memory recording "this mechanism does not do what its name says" is a finding to act on; Correction 1 sat unused a day while its predicted symptom was live, and the diagnosis was re-derived badly twice.

## A prescribed remedy must not assume its own tool exists
Source: [[prescribed-remedy-must-not-assume-its-own-tool-exists]]
- ccmemory v0.13.0 -> v0.13.1. `SESSION_PROTOCOL` (SessionStart hook) v0.13.0 said bare: "Call `ToolSearch("select:mcp__ccmemory__memory_list")` once to try to pull in a late-connecting server." `ToolSearch` exists only with tool-search enabled; a model that correctly detected the missing `memory_list` dead-ended hunting for the tool to find a tool. Observed on gemma-4-26B: searched its tool list for ToolSearch, re-read it, then a `Bash` call whose body was its reasoning pasted as `#` comments.
- Still progress: v0.13.0's target was SILENT failure (no ccmemory reads looks like a project with no memory; model proceeds on false "no prior memory"); that hole closed. Regression: "silently wrong" became "visibly stuck". Do not let one discredit the other.
- Rule for injected "call tool X": (1) gate: "IF, and only if, X is in your tool list"; (2) say X's absence is NORMAL and to SKIP, not hunt; (3) forbid the shell fallback by name (no shell path registers an MCP tool); (4) terminal state reachable from EVERY branch (v0.13.0's "If still unavailable after that, STOP" hung off the ToolSearch branch, so no-ToolSearch had no exit). Write for the least capable model that will read it (including `instenv.prompt` fan-outs).

## ccenvmcp: stdlib MCP shim
Source: [[ccenvmcp-stdlib-mcp-shim]]
- As of 2026-06-13: `ccenvmcp/`, ~250-line stdlib-only Python 3.9+ MCP server shim reproducing the FastMCP slice used. Reason: every `mcp` SDK release requires Python >=3.10, locking out Debian 11 / Raspberry Pi OS, RHEL/Alma/Rocky 9, Ubuntu 20.04. `mcp` was the ONLY hard 3.9 blocker (`nats-py` >=3.7, `watchfiles>=0.21` has a 3.9 abi3 build, all packages use `from __future__ import annotations`).
- API `from ccenvmcp import FastMCP`: `FastMCP(name, instructions=...)`, `@app.tool()` on sync or async, `@app.tool(name=, description=, schema=)`, `app.run()`, `await app.run_stdio_async()`. Newline-delimited JSON-RPC 2.0 on stdio: initialize / notifications/initialized / tools/list / tools/call / ping.
- 3.9 pitfall (`ccenvmcp/ccenvmcp/transport.py`): do NOT use `typing.get_type_hints()` for schemas; under future annotations hints are strings like `"int | None"` and evaluating raises TypeError on 3.9. The shim parses annotation text (`_token_to_schema`; `X | None`/`Optional[X]`/`list[str]`). Tests `ccenvmcp/tests/test_transport.py`.
- Consumers: ccmemory (low-level, 5 tools, explicit `schema=` to keep memory_write `type` enum; `serve()` split into `build_app()`+`serve()`; 0.7.0), ccusage (2 sync tools; 0.2.0), ccteam (9 async tools, instructions=; 0.3.0); `mcp` dropped, requires-python >=3.9.
- Distribution: installed FIRST by top-level install.sh, intentionally NOT a declared dependency (local-source installs; a declared dep would trigger a failing PyPI lookup). See `ccenvmcp/docs/mcp.md`. Related: `ccmemory-debian-build-unknown-install-layout`, `no-per-component-venvs`.

## ccprospect module (v0.1.0, bundle v0.8.0)
Source: [[ccprospect-module-created]]
- Built 2026-07-12 per prospect.md Part IV at `/src/ccenv/ccprospect/`; arch doc `ccprospect/docs/ccprospect.md`; design archive `prospect.md` (do not delete: verbatim GPT consultation and aitrader evidence). Prospective-memory sibling of ccmemory.
- Invariants never to weaken: contracts IMMUTABLE (O_EXCL writes, PreToolUse guard); state = fold of append-only events.jsonl; TWO dimensions attention x resolution. Cancel/supersede close ATTENTION, never RESOLUTION: counterfactual evaluation continues to original expiry with one final evaluation at the boundary (ignores min_interval). Creation refuses already-true predicates (baseline probe); caps are attention budgets (20 active / 8 per day, env-tunable); creation gated while fired items unacknowledged (amend exempt, slot-neutral). session_start predicates fire ONLY in SessionStart-hook evaluations >=1s after creation (covers second-truncated ISO timestamps). Fires latch one-shot; "keep" after fire = attention acked, NOT re-arm (re-arm = amend).
- Owner decisions 2026-07-12: STANDALONE, consumed by projects, no hybrid/sibling watcher in aitrader (spec IV.10 option (a)); price semantics in a small factual probe CLI inside aitrader that contracts call via cmd_*. Binding delivery = `prospect-integrate` skill (`ccprospect/skills/prospect-integrate/SKILL.md`, installed to `~/.claude/skills/`): interactive -> CLAUDE.md block; ccloop -> criteria file (re-fed at every stop-gate); custom-loop -> locate via docs+memory, CONFIRM with user, diff against constitution SOURCE (never hot-edit built artifacts; deploys owner-run). Decision in `.ccprospect/integration.json` (committed, unlike gitignored probe_state.json). Owner pilots in /src/aitrader.
- Deliberate deviations: NO SQLite index in v1 (probe_state.json = local gitignored watermarks/nudge counters; index.db* pre-gitignored); events.jsonl also guarded from hand edits; CLI has read-only inbox/report beyond ccmemory's minimal-CLI rule; NOT alwaysLoad in install.sh (SessionStart HOOK does wake-time work; tools load lazily via ToolSearch).
- Gotchas: ccenvmcp FastMCP line-delimited JSON-RPC, `@app.tool(name=, description=, schema=)` with hand-written schemas; `mcp_server.dispatch` MODULE-LEVEL so surface tests run without ccenvmcp, validate name against SCHEMAS FIRST or unknown tools are masked by the no-store message; Python 3.9: `datetime.fromisoformat` cannot parse Z (use `util.parse_iso`), PEP 604 unions need `from __future__ import annotations` everywhere incl. tests/conftest; event timestamps from store logical clock (`now_utc`, monkeypatchable) so tests drive expiry without sleeps, ack events use real time.
- 72 tests (`python3 -m pytest tests/` from ccprospect/). E2E stdio drive: scratch HOME + `PYTHONPATH=ccprospect:ccenvmcp`, pipe JSON-RPC lines.
