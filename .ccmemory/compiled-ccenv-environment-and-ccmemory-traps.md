## The /src volume (NFS, no xattrs)

- `/src` (`/System/Volumes/Data/src`) is an NFS mount. SQLite WAL needs a shared `-shm` mapping that NFS lacks, so a WAL-mode DB there answers `unable to open database file` to every statement from a Mac client, read-only included. The file is intact (`?immutable=1` works). `connect()` is lazy, so the traceback lands on the first `PRAGMA`, and permissions all look clean. One-step check: byte 18 of the header (2 = WAL, 1 = rollback) plus `mount | grep /src`. Treat WAL as preferred and fall back to `TRUNCATE`. ccmemory's `Store._open` does this and rebuilds an unopenable index, which is safe only because the index is derived. Do not copy rebuild-on-failure to a DB holding original data. [[src-is-nfs-so-sqlite-wal-cannot-open]]
- The same volume cannot store xattrs, so it spawns AppleDouble `._*` sidecars on every write. `COPYFILE_DISABLE=1` does not help (it governs only tar/cp). They corrupt pip wheels (`multiple .dist-info directories`), so install.sh `pip_install_local` stages source to `/tmp`, excluding `._*`/build/dist/egg-info/`__pycache__`, and builds from there. ccmemory 0.6.1 `paths.ensure_gitignore()` ignores `._*` in each store; they cannot be stopped on disk, only kept out of commits. A global `core.excludesfile` with `._*` was proposed but not done (needs user plus git). [[src-tree-appledouble-sidecars]]

## ccmemory internals

- FTS5 `bm25()` IDF is exactly 0 for a term in half the corpus and negative above. Hand-written 8-note fixtures have no signal: same-subject notes scored 0 while a cross-subject note matching a shared rare token scored near the seed. Size fixtures so each term is in well under half the docs (40 notes over 4 subjects worked), give notes unique filler so rare tokens do not leak across groups, and assert behaviour (coverage, disjointness, no mixed subjects), not exact scores. bm25 is negative, more negative is better, and `ORDER BY rank ASC` is best-first, so a candidate is worse than a floor when `hit > floor`. [[bm25-idf-is-zero-on-small-corpora]]
- ccmemory 0.19.0 list budget: on mxfs `memory_list` shipped about 14.9k tokens against a 6,000 budget and held zero project notes or compiled articles. Four interacting defects: `list_all` seeded `spent` with the always-listed set and could not trim it; `reference` was always-listed yet `compile._select` ingested only `project`, so nothing could ever retire it; `compiled-` articles competed with raw notes on mtime and 2 of 132 were listed; `_entry_tokens` under-counted wire size 1.42x and `memory_stats` inherited the error. `count_backlog` also counted non-compilable types, so the compaction nudge could not be silenced by compacting. Invariants: a budget must be able to trim every tier; keep `ALWAYS_LIST_TYPES` small (now `user`, `feedback`); it and `COMPILABLE_TYPES` must stay complementary (test enforces it); count backlog only over what compile can ingest; the estimator must track the serializer (`test_entry_tokens_tracks_real_wire_size`). Method: measure shipped bytes, not self-reported cost, using `tests/measure_list_payload.py` and `tests/simulate_list_policy.py`. [[list-budget-must-trim-every-tier]]

## ccloop

- `keepgoing` returning 0 permits a stop but does not end an interactive TUI. Only the `halt-<session_id>` sentinel watched by `runner.run_session_interactive` does. Before 0.34.1 the criteria-met check sat above the cutoff gate, so a met-criteria session was unreachable by the sentinel and stayed resident (idle for 6+ hours, 510k tokens past a 500k cutoff). Both completion paths now call `_signal_converged()` and log `converged` rather than `halt`. guard.py (PostToolUse) logs `fired <tokens> <sid>` (3 fields) and cannot terminate anything; `keepgoing` writes `halt`/`converged` (4 fields). Repeated `fired` without `halt` means the crossing was noticed and not acted on. Lessons: verify liveness with `ps -o pid,etime,cmd -C ccloop` first and do not infer it from empty logs; compare log field shapes against the writer; tests asserting the sentinel was absent encoded the defect. Campaign criteria that no state can satisfy ("pick the next defect...") produce a premature `criteria-met=YES`, so a run ending early is worth checking for that. [[allowing-a-stop-does-not-end-an-interactive-session]]

## Settings and shipped agents

- Commit attribution is two controls: `includeCoAuthoredBy` (co-author trailer) and `attribution.sessionUrl` (defaults true, writes a `Claude-Session:` URL into history and pushes it). Setting the first alone leaves the second. `coAuthoredBy` is rejected by CLI 2.1.267 (`Unrecognized field`); `includeCoAuthoredBy` is deprecated but the only working key. ccenv v0.32.0's `settings` step seeds `includeCoAuthoredBy:false`, `attribution.commit:""`, `attribution.pr:""`, `attribution.sessionUrl:false` per sub-key. Do not grep the 100MB CLI binary with a greedy fixed-width lookbehind (catastrophic backtracking); anchor on the literal and take trailing context. [[commit-attribution-is-two-controls]]
- Subagents inherit CLAUDE.md as of session start, so a rule requires embedding verbatim in agent definitions. As of v0.31.0 none of grind/scout/miner/memory-compactor embedded any. `grind` (pure shell runner) is the riskiest. Rules a delegated task can violate: git ban, `find /` ban, `rm` shape, `python3`, scripts-not-in-/tmp. Left undone because the user authorized only the two audited items. [[shipped-agents-embed-no-rules]]

## Cost and quota

- Quota has separate weekly buckets (all-models and Fable, plus others via `/api/oauth/usage`). The statusline and `get_context_usage` expose only `five_hour` and `seven_day`, so use `/usage`. A sonnet subagent cannot debit the Fable bucket; Fable requests debit both. Cost is context-weighted (89% of usage was at >150k context), so request counts are proxies, not costs. Delegation helps mainly because output stays out of the parent's context. A +50% weekly promo ended 2026-08-31, so do not calibrate thresholds on measurements from it. Detail in `docs/context-economics.md`. [[quota-two-weekly-buckets-and-context-weighting]]

## ccprospect

- Module (bundle v0.8.0) is the prospective-memory sibling of ccmemory. Invariants: immutable contracts (O_EXCL, PreToolUse guard); state is the fold of append-only `events.jsonl` (also hand-edit guarded); two dimensions, attention and resolution; cancel/supersede close attention only, with counterfactual evaluation to expiry; creation refuses already-true predicates; caps 20 active / 8 per day; creation gated while fired items are unacked; `session_start` predicates fire only in SessionStart evaluations at least 1s after creation; fires latch one-shot and "keep" is an ack, not a re-arm (amend re-arms). Decisions: standalone and consumed by projects (no watcher inside aitrader); binding via the `prospect-integrate` skill; no SQLite index in v1; not alwaysLoad. Gotchas: ccenvmcp FastMCP uses hand-written schemas; keep `mcp_server.dispatch` module-level and validate the tool name against SCHEMAS first; Python 3.9 needs `util.parse_iso` and `from __future__ import annotations`; store events use a monkeypatchable logical clock. [[ccprospect-module-created]]
- Live pilot: itrader (opus) filed a real anticipatory contract (p-0001, pre-open playbook) and a reasoned NO_CONTRACT. atrader (gemma) declined honestly (NO_CONTRACT), the preferred failure mode of decline over fabricate. Reads on a missing store create nothing. `PROSPECT.md` appears only at the next session start, which is not a bug. Contracts are intention-shaped, so the calibration record stays empty unless expect+bucket are encouraged (never required). [[ccprospect-aitrader-first-cycle]]
