## The /src volume (NFS, no xattrs)

- `/src` (and `/System/Volumes/Data/src`) is an NFS mount from 192.168.1.4, not local disk: `192.168.1.4:/src on /System/Volumes/Data/src (nfs, nodev, nosuid, automounted, noowners, nobrowse)`. SQLite WAL needs a shared `-shm` mapping that NFS lacks, so a WAL-mode DB there answers `OperationalError: unable to open database file` to every statement from a Mac client, read-only open included. The file is intact: `open(path,'rb')` reads `SQLite format 3`, and `?immutable=1` opens and queries it. `connect()` is lazy, so the traceback lands on the first `PRAGMA` and reads like a pragma problem; directory/file permissions are fine and a plain write to the directory succeeds, so every permission check is clean. One-step check: `python3 -c "d=open(PATH,'rb').read(100); print('write_version', d[18])"` (2 = WAL, 1 = rollback journal) plus `mount | grep /src`. Treat WAL as preferred, not assumed, and fall back to `TRUNCATE`. ccmemory's `Store._open` does this and also rebuilds an index it cannot open, which is safe only because the index is derived from the `.md` files. Do not copy rebuild-on-failure to a DB holding original data. The AppleDouble sidecars are the same volume's doing; see [[ccenv-installed-vs-source-version]] for the other half of the install-path confusion. `src-is-nfs-so-sqlite-wal-cannot-open`
- The volume cannot store macOS xattrs, so the OS materializes AppleDouble `._*` sidecars next to anything written (`._README.md`, `._direct.js`, ...). `COPYFILE_DISABLE=1` does not help (it governs only tar/cp, not FS-level creation). Symptom: `pip install` of a local package fails with `invalid wheel, multiple .dist-info directories found: ._<pkg>.dist-info, <pkg>.dist-info`; during `bdist_wheel` setuptools writes `<pkg>.dist-info/`, the FS drops the sidecar beside it, and the zip step sweeps both in. Fix in install.sh `pip_install_local`: stage source to `/tmp` (native APFS), excluding `._*`/`build`/`dist`/`*.egg-info`/`__pycache__`, build from the clean copy; all local pip installs (ccmemory/ccloop/ccteam/overlays) route through it. `.ccmemory/` dirs also accumulated `._*.md` sidecars that the index scan picked up as junk; ccmemory v0.6.1 `paths.ensure_gitignore()` writes `._*` into each store's `.gitignore` (kept out of commits, not off disk). A global `core.excludesfile` with `._*` would cover all source-tree sidecars at once but was NOT done (needs user plus git). Related: [[pythonuserbase-in-zshenv]]. `src-tree-appledouble-sidecars`

## ccmemory internals

- FTS5 `bm25()` IDF is `log((N - n + 0.5)/(n + 0.5))`: exactly 0 for a term in half the corpus, negative above. Measured building `compile.compaction_plan` (ccmemory 0.19.0): a fixture of 4 notes on one subject and 4 on another scored, for the seed's own query: `-0.9823 unit-note2` (seed), `-0.9301 xfs-note2` (other subject, matched only the shared rare token "note2"), `-0.0000 unit-note0`, `unit-note1`, `unit-note3` (same subject, every term shared, IDF 0). Clustering code was correct; fixture had no signal. 40 notes across 4 subjects (n/N = 0.25, IDF about 1.07) behaved like the real store. Never unit-test similarity/ranking/clustering on a toy corpus; size fixtures so each term is in well under half the docs; assert behaviour (coverage, disjointness, no mixed subjects), not exact scores. Avoid leaking tokens across groups (`xfs-note3`/`unit-note3` share rare `note3`): give each note unique filler. bm25 is negative, more negative is better, `ORDER BY rank ASC` is best-first, so a candidate is worse than a floor when `hit > floor`. `bm25-idf-is-zero-on-small-corpora`
- ccmemory 0.19.0 list budget: on mxfs (1,848 memories) `memory_list` shipped about 14.9k tokens against a 6,000 budget while `memory_stats` reported 10,490, and the listing held zero project notes and zero compiled articles: 180 entries, all reference/feedback/user. Paid before the first user message every session and on every ccloop relay. Four interacting defects: (1) `Store.list_all` seeded `spent` with the full always-listed set and trimmed only the remainder, so once those types alone exceeded the budget the loop broke on the first project note; (2) `reference` was in `ALWAYS_LIST_TYPES` while `compile._select` ingested only `type='project'`, so nothing could ever retire a reference memory (write-only type, 160 entries); (3) `compiled-` articles competed with raw notes on mtime alone, 2 of 132 listed, so folding retired 1,494 notes in favour of articles then withheld; (4) `_entry_tokens` modelled `name+description+30` while the server shipped `json.dumps(indent=2)`, under-counting 1.42x, and `memory_stats` inherited it. Also `count_backlog` counted every type while only `project` was actionable, giving mxfs a backlog floor of 144 against threshold 20, so the compaction nudge fired every session and could not be silenced by compacting. Invariants: a budget must trim every tier including the first (un-trimmable tier makes it advisory); `ALWAYS_LIST_TYPES` stays small, now `("user","feedback")` (reference is a durable fact reached by BM25 search); it and `compile.COMPILABLE_TYPES` must stay complementary (`test_compilable_and_always_listed_types_are_complementary`); an unsilenceable alarm is broken, so count backlog only over what compile can ingest; estimator must track serializer (`test_entry_tokens_tracks_real_wire_size`). Method: do not trust self-reported cost (`memory_stats.list_tokens_actual` said 10,490, `len(json.dumps(payload))` said 14,921); measure shipped bytes with `tests/measure_list_payload.py` and `tests/simulate_list_policy.py` (opens `index.db` `mode=ro`, simulates policy changes against real stores before code; it surfaced defect 3, absent from the original diagnosis). Checked and cleared: 33 mxfs rows have frontmatter `name:` differing from filename (legacy prose-titled, e.g. `feedback_commits.md` -> `name: Commits only when work is done/working`); index keys on frontmatter name and stores `path`, so `memory_get` resolves; 0 dead paths, 0 unindexed files. `list-budget-must-trim-every-tier`

## ccloop

- `keepgoing` returning 0 PERMITS a stop but does not END a session. Headless `-p`: a permitted stop exits. Interactive TUI: returns to the prompt and stays resident; only the watcher in `runner.run_session_interactive` seeing `<run-dir>/halt-<session_id>` terminates it. Defect (fixed ccenv 0.34.1): `if _criteria_met(run_dir): return 0` sat above the cutoff gate (`cutoff = _read_cutoff(run_dir)`; `if cutoff > 0 and tokens >= cutoff: _signal_halt(...)`, the only sentinel writer), so once `criteria-met` went YES the sentinel was unreachable. A run met criteria at 11:39 and its session was still resident and idle at 18:16, drifted to 510k tokens past a 500k cutoff. Both completion paths now call `_signal_converged()` and log `converged`, distinguishable from a cutoff `halt`. Two cutoff paths: guard.py (PostToolUse) logs `fired <tokens> <sid>` (3 fields) and cannot terminate anything; `keepgoing`/`_signal_halt` writes `halt`/`converged` (4 fields). Repeated `fired` with no `halt` means the crossing was noticed and nothing acted, which reads deceptively like "cutoff works but is ignored". Lessons from getting it wrong twice: verify liveness with `ps -o pid,etime,cmd -C ccloop` as the FIRST call (concluded "parent exited" from 0-byte `sessions.log` and a converged run; parent was alive 3h29m in); compare log field shapes against the writer; tests asserting the sentinel was ABSENT encoded the defect (honest assertion: sentinel present, event `converged`). Campaign criteria no state can satisfy ("pick the highest-severity open defect ... and move to the next one") produce a premature `criteria-met=YES`; before 0.34.1 a silent park, now a clean early exit; a run ending early is worth checking for `criteria-met` reappearing. `allowing-a-stop-does-not-end-an-interactive-session`

## Settings and shipped agents

- Commit attribution is two controls: `includeCoAuthoredBy` (`Co-Authored-By: Claude ... <noreply@anthropic.com>`) and `attribution.sessionUrl` (defaults true; writes a `Claude-Session: https://claude.ai/code/session_...` line into history permanently and pushes it to the remote). Verified live 2026-09-10: `includeCoAuthoredBy: false` alone dropped the co-author line and kept the session line; both gone only after `attribution.sessionUrl: false`. `coAuthoredBy` (recommended by blogs and a web search summary) is rejected by CLI 2.1.267: `Settings validation failed: - : Unrecognized field: coAuthoredBy` (Edit validates against the CLI schema, so it fails loudly). `includeCoAuthoredBy` is marked deprecated in the schema but is the only working key. Schema is embedded in the binary at `~/.local/share/claude/versions/<ver>`, readable via `grep -ao "Claude-Session.\{0,60\}"`. Config lives in `~/.claude/settings.json`; ccenv v0.32.0's `settings` step seeds `includeCoAuthoredBy:false`, `attribution.commit:""`, `attribution.pr:""`, `attribution.sessionUrl:false` per sub-key, so a deliberately-set commit trailer survives. Do not grep the ~100MB ELF with a greedy fixed-width lookbehind like `grep -ao ".\{700\}sessionUrl"` (catastrophic backtracking, never returns); anchor on the literal and take trailing context. `commit-attribution-is-two-controls`
- Subagents inherit CLAUDE.md as of session start, and `.claude/agents/*.md` is registered then too, so a rule needs embedding verbatim in agent definitions (ccenv v0.31.0 added this bullet to RULE FOUR). None of the four shipped definitions in `/src/ccenv/agents/` does: `grind.md` (Bash/Read/Grep/Glob, model sonnet; its rules are reporting discipline: raw evidence, never silently truncate, batch aggressively; pure shell runner, riskiest), `scout.md`, `miner.md`, `memory-compactor.md` (same, narrower blast radius). Not broken in practice because inheritance covers rules existing before session start; it breaks quietly for a rule authored mid-session. Rules a delegated task can violate: git ban (RULE TWO), `find /` ban (box overlay already restates for subagents: "This applies to subagents too - do not delegate a `find /` you are not allowed to run yourself", the precedent wording), `rm` permission-prompt shape (RULE SEVENTEEN), `python3` not `python` (RULE SIXTEEN), scripts-never-in-`/tmp` (RULE FIVE). Left undone: the user authorized only the two audited items and nothing adjacent, so the gap was reported. `shipped-agents-embed-no-rules`

## Cost and quota

- Measured from `/usage` and the 2.1.239 binary, 2026-08-22: session (5-hour) 15%, week all models 19%, week Fable 25%. The CLI tracks six windows (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, `seven_day_overage_included`, `overage`) via `GET /api/oauth/usage` (`fetchUtilization`). A sonnet subagent request cannot debit the Fable bucket (settles the delegation proposal's premise), but it is a transfer: a Fable request debits both buckets, a sonnet one only all-models; delegation pays until all-models binds; at the measured mix Fable binds (25% vs 19%). `get_context_usage` and the statusline expose only `five_hour` and `seven_day`, so the loop's meter cannot see the bucket that exhausts; use `/usage`. A +50% weekly promo ran through 2026-08-31; do not calibrate thresholds on measurements from it. Cost is context-weighted: `/usage` states "89% of your usage was at >150k context. Longer sessions are more expensive even when cached." The mxfs cost-audit's "~4,430 Fable requests/week" and request-count shares are proxies from one stable context profile; reject "every request costs the same regardless of size". Delegation's real mechanism: grind output never enters the parent's context, lowering context growth per request and extending work span inside the unchanged 500k cutoff. Full write-up `/src/ccenv/docs/context-economics.md` (also: gate subagent pass-through on `agent_id` not `agent_type`; `PreToolUse` supports non-blocking `additionalContext`; a denied tool call has already cost its request). `quota-two-weekly-buckets-and-context-weighting`

## ccprospect

- Module `/src/ccenv/ccprospect/` (v0.1.0, bundle v0.8.0, built 2026-07-12 per prospect.md Part IV), prospective-memory sibling of ccmemory; arch doc `ccprospect/docs/ccprospect.md`; design archive `prospect.md` (do not delete: verbatim GPT consultation and aitrader evidence). Invariants: contracts immutable (O_EXCL writes, PreToolUse guard); state = fold of append-only `events.jsonl`; two dimensions attention x resolution; cancel/supersede close attention only, counterfactual evaluation continues to original expiry with one final evaluation at the boundary (ignores min_interval); creation refuses already-true predicates (baseline probed once at creation); caps are attention budgets, 20 active / 8 per day, env-tunable; creation gated while fired items unacknowledged (amend exempt, slot-neutral); `session_start` predicates fire only in SessionStart-hook evaluations at least 1s after creation (mid-session inbox calls must not fire them; 1s covers second-truncated ISO timestamps); fires latch one-shot, "keep" after fire is an ack, not a re-arm (re-arm = amend). Owner decisions: standalone, consumed by projects, no hybrid/sibling watcher in aitrader (spec IV.10 option (a)); price semantics belong in a small factual probe CLI inside aitrader that contracts call via `cmd_*`; binding via `prospect-integrate` skill (`ccprospect/skills/prospect-integrate/SKILL.md`, installed to `~/.claude/skills/`): interactive -> CLAUDE.md block, ccloop -> criteria file (re-fed at every stop-gate), custom-loop -> locate via docs+memory, CONFIRM with user, diff against constitution SOURCE (never hot-edit built artifacts; deploys owner-run); decision persisted in `.ccprospect/integration.json` (committed, unlike gitignored `probe_state.json`); owner pilots it in `/src/aitrader`. Deviations: no SQLite index in v1 (cheap fold at cap 20; `probe_state.json` is local gitignored watermarks/nudge counters; `index.db*` pre-gitignored); `events.jsonl` also guarded from hand edits (event log is the outcome record); CLI has read-only inbox/report subcommands beyond ccmemory's minimal-CLI rule; not alwaysLoad in install.sh (SessionStart hook does wake-time work independent of MCP; tools load lazily via ToolSearch). Gotchas: ccenvmcp FastMCP is line-delimited JSON-RPC on stdio, `@app.tool(name=, description=, schema=)` with hand-written schemas; keep `mcp_server.dispatch` module-level (not a closure) so surface tests run without ccenvmcp, and validate the tool name against SCHEMAS first or unknown tools are masked by the no-store message; Python 3.9 `datetime.fromisoformat` cannot parse Z, so use `util.parse_iso`, and PEP 604 unions need `from __future__ import annotations` everywhere including tests/conftest; created/fired/expired events use the store's logical clock (`now_utc`, monkeypatchable) so tests drive expiry without sleeps, ack events use real time. 72 tests (`python3 -m pytest tests/` from ccprospect/); E2E stdio drive pattern: scratch HOME + `PYTHONPATH=ccprospect:ccenvmcp`, pipe JSON-RPC lines. `ccprospect-module-created`
