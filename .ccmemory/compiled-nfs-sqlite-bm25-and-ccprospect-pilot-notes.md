Topic: SQLite behaviour traps hit by ccmemory (NFS WAL, FTS5 bm25 on toy fixtures), plus one loosely related ccprospect pilot record.

## /src is NFS: WAL-mode SQLite cannot open
- `/src` (and `/System/Volumes/Data/src`) is an NFS mount from 192.168.1.4: `192.168.1.4:/src on /System/Volumes/Data/src (nfs, nodev, nosuid, automounted, noowners, nobrowse)`. WAL needs a shared `-shm` mapping, which NFS lacks, so a WAL-mode DB there answers `OperationalError: unable to open database file` to every statement from a Mac client, even read-only. File intact: `open(path,'rb')` reads `SQLite format 3`; `?immutable=1` opens and queries. [[src-is-nfs-so-sqlite-wal-cannot-open]]
- One-step check: `python3 -c "d=open(PATH,'rb').read(100); print('write_version', d[18])"` (2 = WAL, 1 = rollback journal); `mount | grep /src`. Misleading symptoms: `connect()` is lazy so the traceback points at the first `PRAGMA`; permissions are fine and plain writes to the dir succeed. [[src-is-nfs-so-sqlite-wal-cannot-open]]
- Anything storing SQLite under `/src` treats WAL as preferred and falls back to `TRUNCATE`. ccmemory `Store._open` does so and rebuilds an index it cannot open, safe only because the index derives from the `.md` files; do not copy rebuild-on-failure to a DB holding original data. AppleDouble `._*` sidecars are the same volume's doing; see `ccenv-installed-vs-source-version`. [[src-is-nfs-so-sqlite-wal-cannot-open]]

## FTS5 bm25 IDF is zero on small corpora
- IDF = `log((N - n + 0.5)/(n + 0.5))` is exactly 0 for a term in half the docs, negative above. Measured building `compile.compaction_plan` (ccmemory 0.19.0), 4 notes on one subject + 4 on another: seed's own query scored `-0.9823 unit-note2` (seed), `-0.9301 xfs-note2` (other subject, matched only shared rare token "note2"), `-0.0000` for unit-note0, unit-note1, unit-note3 (same subject, all terms shared). Clustering code was correct; fixture had no signal. 40 notes across 4 subjects (n/N = 0.25, IDF ~1.07) behaved like the real store. [[bm25-idf-is-zero-on-small-corpora]]
- Lessons: never unit-test similarity/ranking/clustering on a toy corpus; size so each term is in well under half; assert real behaviour (coverage, disjointness, no mixed subjects), not exact scores. Avoid tokens leaking across groups (`xfs-note3`/`unit-note3` share rare `note3`); give each note unique filler. [[bm25-idf-is-zero-on-small-corpora]]
- FTS5 `bm25()` returns negative values, more negative = better; `ORDER BY rank ASC` is best-first; a candidate is worse than a floor when `hit > floor`. [[bm25-idf-is-zero-on-small-corpora]]
