Assorted group (clusterer tail): nine user corrections with no single topic. Common thread: do not assume, do not enforce, do not over-reach. Organised by theme.

## Verify before relaying

### Our own prose is a claim, not evidence
A rationale in this repo's CHANGELOG, docs or docstrings written by an earlier Claude session is a claim. Before relaying or designing on it: external-policy claims (billing, pricing, API behavior) are checked against the vendor's current page with a web search; behavioral claims against a transcript or measurement. `changelog-rationale-is-not-evidence`

- False claim 1: "`claude -p` bills a separate metered API-rate credit pool." Anthropic announced it 2026-05-14 for 2026-06-15 and paused it on 2026-06-15; it never took effect. support.claude.com article 15036540 (update dated 2026-10-07) says `claude -p` and the Agent SDK can still be used with subscription limits; Max/Team plans also get monthly API credits that cover it. ccmemory removed its `claude -p` compile path over this and ccloop gated `--headless` behind `--accept-api-cost`. Both corrected in bundle v0.38.0.
- False claim 2: "Compactor agents dispatched at session start make the session wait ~90s." ccmemory v0.20.0 removed automatic compaction over this; no transcript was ever cited. The memory-compactor always ran as a background agent and never blocked the turn (the user had watched it). With nothing dispatching, one store's backlog reached 165 notes and its feedback memories overflowed even a feedback-only `memory_list`. Dispatch restored in ccmemory v0.21.0.
- Agent-tool subagents run inside the live session and never involve `claude -p`; whatever `claude -p` costs, it was never a reason to stop background compaction.
- Why: the user had to push back twice ("do a damn web search"). Each claim was read out of the tree and repeated with confidence. How to apply: when the only source is our own prose, say so; verify before stating it as fact and before any change that depends on it.

### ccloop `--cutoff`: never propose lowering it
User experiment, about 2 weeks, reverted 2026-08: `--cutoff=500` -> `--cutoff=145` -> back to 500. 145 lost even though it kept sessions under the 150k "expensive" threshold. A ccloop session reaches ~70k tokens of context before the first real work; that fixed cost is rebuilt on every restart. `ccloop-cutoff-lowering-already-tried-and-lost`

- cutoff 145k -> ~75k of work per session -> ~93% fixed-cost overhead; cutoff 500k -> ~430k of work -> ~16% overhead.
- User: "we burned so many tokens in that short period that it made it not worth it... I set it back to 500 and yes it costs more at the top end, but we don't end up with the constant restart churn."
- Measured 2026-08-22 with `scripts/startup_context_audit.py` over 409 mxfs sessions (S = first assistant turn's total prompt tokens, exact): CLI 2.1.239 S = 65,075 median. S grew 40,799 (2.1.217) -> 65,075 (2.1.239), +24k (+59%) in ~22 releases, ~+1.3k per release. Attribution: ~47k CLI floor (not ours), ~8.8k project CLAUDE.md, ~4.0k ccloop session prompt, ~2.2k global CLAUDE.md, ~3k agents/ccmemory. MCP tool schemas are already deferred (`ENABLE_TOOL_SEARCH`; every sampled 2.1.239 session used ToolSearch) - that lever is spent.
- ~75% of S is not ours; perfect work on everything we own saves ~8k of 65k, nowhere near enough for 145k to win.
- Standing rules: (1) do not propose lowering the cutoff, not even "until S is reduced"; (2) the only remaining lever is delta, context growth per request - keep grind output out of the parent context via subagent delegation; (3) trimming the 35 KB mxfs CLAUDE.md is housekeeping (~4k/session for a 50% cut), not strategy. Full analysis: `/src/ccenv/docs/context-economics.md`.

## Where things go
- No version history in any CLAUDE.md, top-level or per-module. Trigger: `ccmemory/CLAUDE.md` had a 90-line "Architecture history" section listing v0.1.0 to v0.9.0. User: "why is history being kept in CLAUDE.md in _any_ project versus CHANGELOG.md???" and directed all module-level CLAUDE.md files be cleared of history and removed entirely (their architecture content already duplicated README.md). `no-version-history-in-claude-md`
  - Why: CLAUDE.md loads every session; only release work needs history, and it can Read `CHANGELOG.md` on demand.
  - Never add "## Architecture history" / "## Version history" / "## Changelog" sections. Releases go in that component's `CHANGELOG.md` (`## vX.Y.Z` headers, newest on top, create if absent). Per-module CLAUDE.md files are deprecated; the top-level `/src/ccenv/CLAUDE.md` is the global-rules file installed to `~/.claude/CLAUDE.md`; subdirectory architecture/install/test info goes in that directory's `README.md`. A "this version did X, the next added Y" paragraph belongs only in CHANGELOG.md or a commit message. Related: `ccenv-installed-vs-source-version` (single source of truth per concern).
- Never instruct a session to maintain a handoff/state/summary doc - not as a tier, with a freshness check, or "just a short one". User (2026-08-14), blunt and repeated: it "has cost me millions in tokens". Supersedes the 0.20.0 decision `handoff-docs-must-be-freshness-stamped`; ripped out of ccloop in v0.21.0. `never-make-sessions-maintain-handoff-docs`
  - Instead: Claude Code writes a full transcript to `~/.claude/projects/<cwd-slug>/<session-id>.jsonl`. User's own handoff has long been one line: "read previous claude code session for context".
  - ccloop `runner.prior_session_transcript`, deterministic, two tiers: (1) within a run, `sessions.log` holds session-ids in order; the last whose transcript still exists is the predecessor (walk backwards so a deleted transcript falls through); (2) first session of a run: newest non-empty `.jsonl` in the cwd-slug dir, excluding this run's own ids. Nothing to point at -> emit nothing; never name a nonexistent path.
  - The pointer ships with size, line count, a suggested `Read` offset near the tail (`lines - 300`) and a `grep` example, since a multi-megabyte JSONL read whole would blow the context it was meant to save.
  - Transcript wins: free, cannot go stale (no mtime checks, STALE markers, scraped fallbacks - all 0.20.0 machinery), complete (tool results and reasoning). Non-Anthropic API backends driving `claude` can't be relied on to know their transcript path, so the wrapper computes and states it.
- Scripts are never temp files; the split is by kind, not predicted lifetime (ccenv v0.18.1, 0.18.0->0.18.1, CHANGELOG + `docs/install.md` History). The v0.13.3 wording ("might be used again" -> `tests/`, truly temporary -> /tmp) failed because the prediction was reliably wrong; every script came with a story why it was throwaway and got wiped on reboot. `scripts-never-go-in-tmp`
  - Test harness, debug probe, repro case, one-off migration, data-munger, helper -> repo: harnesses/probes/repros in `tests/`; utilities/ops/build helpers in `tools/` or `scripts/` (whichever exists; create `scripts/` if neither). /tmp is data only: scratch output, downloaded blobs, throwaway fixtures, intermediate dumps.
  - Tension: the harness scratchpad `/tmp/claude-<uid>/.../scratchpad` says all temp files go there; CLAUDE.md overrides that for anything executable; scratchpad is single-use data only.
  - Compatible with `test-destructive-scripts-against-fixtures-only`: the fixture tree is data and lives in /tmp; the script operating on it does not. Landed in `/src/ccenv/CLAUDE.md` (verbatim `[CCENV MANAGED]` source) and mirrored byte-identically into `~/.claude/CLAUDE.md` ahead of the next install. See `repo-claude-md-is-managed-block-source`.

## Enforcement and installers
- ccenv v0.33.0 deleted all three ccproject awareness hooks (`track` PostToolUse, `sync` Stop, `status` SessionStart) and `awareness_hooks.py`. `enforcement-hooks-that-check-file-written`
  1. Per-session state with no cleanup: `track` wrote `.claude/awareness/.state/touched-<session-id>.json` on every Edit/Write; nothing deleted them; 810 accumulated in /src/mxfs. Each hook invocation is a fresh process, so it was cross-process scratch memory given unbounded lifetime by omission. 141 KB of JSON occupied 3.3 MB on disk (~170-byte files burning a 4 KB block each; `du -sh` and `du -sb --apparent-size` disagree 23x - quote both). Not gitignored: 810 session IDs as commit candidates where the instruction is to stage everything.
  2. Enforcement measuring the wrong thing: `sync` blocked session end until a subsystem doc was edited; it could check only WHETHER the file was written, not whether it said anything true, so a no-op write satisfied it, and it demanded prose when a session is least able to write any. Measured over 810 sessions: nudges=0 621, nudges=1 118, nudges=2 39, nudges=3 (cap) 32. The 32 were blocked three times then let through with no doc update: ~96 re-fed turns for nothing. A gate whose predicate is "the artifact was touched" is a formality with a cost; if a check cannot distinguish compliance from a no-op it gets the no-op.
  3. mtime is not a drift signal: `status` compared source mtime to doc mtime and injected it at SessionStart. Checkout, branch switch or reformat bumps every mtime; /src is NFS-shared, muddling mtimes across machines. Its consumer was the model; the user never read it (never displayed to them).
  - Migration: removing a hook from an installer is not enough - boxes that ran the old installer still have it in `~/.claude/settings.json`. ccproject installer step 5 was converted from register to UNREGISTER (else every Edit/Write spawns python3 at a deleted script): strip only hooks whose command names the script, drop an entry whole when that was its only hook (no empty matcher stubs), delete the stale installed script. Test against a copy of a REAL settings.json (it had nine unrelated ccloop/ccmemory hooks on those events): three removed, nine untouched.
- Installers seed, never overwrite. ccenv v0.22.0 added `install_ccenv_settings()` to `install.sh` (step `settings`, right after the base CLAUDE.md is assembled), writing `env.CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK = "1"` (kills the refusal fallback that silently re-runs a turn on a different model) and `switchModelsOnFlag = false` (belt and braces; costs a dialog instead of a silent swap). `installer-seeds-settings-never-overwrites`
  - First cut enforced both values and rewrote a differing key. User cut in mid-implementation: "now make sure you dont set it if its already there."
  - Rule: seed a MISSING key; a present key is a deliberate user choice whatever the value; print `already set, left alone: <key>=<value>`; when nothing was added, do not rewrite the file (mtime is a signal). Generalizes to any ccenv install path touching user config (`settings.json`, shell env files, `.claude.json`): add-if-missing, never enforce-my-value. Exception: wiring ccenv fully owns (its own hook entries and MCP registrations), where healing a stale path is the point.
  - Tests: `tests/test_settings_step.sh` lifts the function out of `install.sh` by name (`sed -n '/^install_ccenv_settings() {$/,/^}$/p'` + `eval`) and runs it against throwaway /tmp HOME fixtures; 19 assertions incl. present-value-kept and file-not-rewritten.
- Copy-paste commands in install output (REQUIRED-setup banner and similar) must be ONE physical line, never `\` continuations, one `echo` per command, no multi-line heredocs to retype. User: "THIS _MUST_ be 1 line!!! MUST". Continuations break under terminal wrap, partial selection, some SSH-client pastes, reading aloud. Bad: `grep -q PYTHONUSERBASE $HOME/.zshrc 2>/dev/null || \` newline `echo 'export PYTHONUSERBASE="$HOME/.local"' >> $HOME/.zshrc`; good: the same on a single line. `one-line-copy-paste-commands`

## Destructive scripts
`test-destructive-scripts-against-fixtures-only` (2026-07-25, building `/src/ccenv/uninstall.sh`). After building a correct fixture in the scratchpad, Claude ran `./uninstall.sh --only ccprospect --only ccinsight --project "$FIX" -y --keep-packages`. `--project` pointed at the fixture, but `--only` still applied to everything else the script discovers (all 47 known project dirs plus the whole user-scope harness), and `-y` bypassed the confirmation prompt that existed to stop this. Unannounced live changes: `~/.claude/settings.json` lost 7 ccprospect/ccinsight hooks; `~/.claude.json` lost both MCP registrations; `~/.claude/skills/{prospect-integrate,ccinsight-integrate}/` deleted; `/src/trader/.ccprospect/` (PROSPECT.md, probe_state.json, .gitignore) hard `rm -rf`'d with no backup. The user was retiring them anyway but had asked to CREATE the uninstaller first and handle archiving themselves; timing and consent were not Claude's to assume.
1. Destructive script: `--dry-run` on the live system; real run ONLY in a throwaway fixture. If it can't be pointed exclusively at the fixture, no real run.
2. `-y` / `--force` / `--yes` is never for testing.
3. `--only X` scopes component, not directory; check what a scope flag bounds.
4. "User wants this gone eventually" is not authorization now; build, show, let them pull the trigger.
- Design fix: `purge_project_state()` tars every state dir into `~/ccenv-uninstall-<stamp>/` before `rm -rf` and skips deletion if tar fails. Uninstallers removing state with no other copy must archive first; uncommitted files are unrecoverable and git is banned as a restore path.
